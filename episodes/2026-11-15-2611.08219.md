Agent-R2: Scaling Agents for Realistic Productivity Work via Real-Source Data Synthesis, by Teng Pan, Zixuan Wang, and Yuchen Yan, from Zhejiang University and Baidu, is a data synthesis pipeline for training small agents on realistic office work, and its result is that a 4 billion parameter model trained on 4,000 synthesized instances beats a 235 billion parameter thinking model on the GDPval productivity benchmark, scoring 51.0 percent pass at one against 48.0 percent. The method's core claim is that the bottleneck for productivity agents is not more synthetic data but data grounded in real work: real occupational intents, authentic messy files, and deliverable-level evaluation rubrics.

The problem setup is specific. A realistic productivity task is a long-horizon professional job in a sandbox with general tools, heterogeneous input files, and fine-grained deliverable requirements. The task instance is a tuple of a user instruction, an attachment set available during solving, an optional reference set used only for evaluation, and a task-specific rubric. The agent's job is to produce a set of deliverable files, and the tools are bash for shell commands and file operations, web search, web fetch, and view image for looking at rendered pages. The authors' argument about why existing training data fails is threefold. Real workflows have interdependent steps and implicit conventions, real file contexts are heterogeneous and incomplete in ways generated files never are, and producing an output file is not the same as meeting deliverable standards for factual consistency, evidence coverage, structure, and formatting. Existing datasets target each of those in isolation: instruction following, general reasoning, document question answering, or single-type deliverables like slides or spreadsheets. None of them jointly covers real intent, cross-file evidence, workflow execution, and deliverable constraints, which is what end-to-end supervision would have to teach.

The synthesis pipeline has three stages, and the design choice running through all of them is that every stage is grounded in real sources rather than LLM fabrication. Stage one is workflow extraction. They start with occupational activity seeds drawn from O*NET, the standard occupational database, and a web corpus from the DLR-Web dataset, which itself is filtered from FineWeb. Each corpus segment carries discipline metadata that maps to an occupational category, and the segment is paired with the matching seeds. A synthesis model, Qwen 3.6 Plus, extracts a file-oriented workflow blueprint from the segment under two filters: it must be a genuine multi-step workflow, and it must be file-oriented, meaning the work requires locating, reading, editing, or producing file artifacts. The blueprint captures information dependencies, required file types, and expected outputs. This is the scalability move: manually authored workflows do not scale, but web corpora contain workflow evidence everywhere, and the extraction turns that evidence into reusable blueprints.

Stage two is attachment searching. For each blueprint, the synthesis model runs a multi-turn search-and-verification loop in the sandbox. It generates a search query conditioned on the workflow, the required file types, and its own previous queries and results, runs web search, checks each result's title and snippet for relevance, then downloads promising candidates and inspects them with bash and view image, looking at cover pages and tables of contents. Files verified as relevant are retained, and there is a practical size cap: files longer than 50 pages or larger than 2 megabytes are discarded to control download latency and construction cost. The loop stops when the retained files jointly satisfy the workflow's information and operation needs, or the search turns run out, and unsatisfied instances are simply dropped. The point of this stage is that the attachment sets keep the natural complexity of real documents: the layouts, the gaps, the cross-file references, none of which generated files reproduce well.

Stage three is task synthesis inside the sandbox. Candidate files are rendered into page images and spreadsheets parsed into sheet-level tables, and the synthesis model inspects the contents, fetches web evidence where the workflow needs online information, and decides which candidates form the attachment set. It then writes the user instruction and the rubric. The instructions require complex deliverables that involve evidence gathering, reasoning, file operations, and artifact construction, and the rubrics specify detailed criteria for evidence grounding, analytical correctness, and deliverable quality. The paper includes a reference synthesis and a check-and-correct loop, so that a reference answer exists which actually satisfies the rubric before the instance is kept. Out of 10,000 web-corpus candidates, this yields 4,000 high-quality training instances, a 40 percent survival rate, which is a reasonable quality bar for a pipeline like this.

Training is staged. Agent-R2-4B is built from Qwen 3 4B Thinking, first supervised fine-tuning on the synthesized trajectories, then rubric-based reinforcement learning. The RL stage runs rollouts in the persistent sandbox and gives outcome rewards computed against the fine-grained rubric, so the model is rewarded for satisfying evidence, reasoning, and artifact-quality requirements rather than merely producing a file that exists. That distinction is the whole point of rubric-based rewards over file-exists rewards, and it is where the deliverable-level evaluation standard from the data stage gets enforced during training.

The results. On GDPval, the full set, Agent-R2-4B scores 51.0 percent pass at one, an 18.6 point improvement over its 32.4 percent base model, and it beats Qwen 3 235B A22B Thinking 2507 at 48.0 percent, Qwen 3 VL 235B at 49.7 percent, GPT-4.1 at 48.8 percent, and DeepSeek v3.1 at 49.7 percent. For context from their figure, Claude Opus 4.5 sits at 72.6 percent and GLM 4.7 at 61.1 percent, so the 4B model is still well short of the frontier, but it has crossed the 235B open-weight thinking model on this benchmark, and it also sits above Qwen 3 30B A3B at 35.0 percent and the base Qwen 3 4B at 32.4 percent, which is the internal comparison that matters most for judging what the 4,000 instances actually contributed. On OfficeQA, a document-grounded reasoning benchmark, the base model scores 2.2 percent and Agent-R2-4B reaches 14.8 percent, again ahead of the 235B model at 13.8 percent. The behavioral analysis is the second contribution: they find the training mitigates shortcut behavior, where agents emit superficially plausible deliverables before grounding, constructing, or verifying them, and promotes sustained exploration instead.

The skeptical assessment. First, the benchmark gap this paper closes is real, and the 4B beating 235B result is the kind of result that comes from task-specific data doing genuine work, but I would want to see whether the GDPval advantage survives on held-out tasks that were not in the same occupational distribution as the training instances. The workflow blueprints come from web corpus segments mapped to O*NET categories, and if GDPval's task mix overlaps heavily with the training occupations, the generalization claim is weaker than the headline. The 10,000-to-4,000 funnel is good, but the paper does not deeply analyze what gets filtered out, and the failure modes of the pipeline, blueprints whose real files simply do not exist publicly, for instance, would tell you where the method's ceiling is. Second, the rubric-based RL is the part I would re-verify before adopting it. Rubric scores as RL rewards are notoriously easy to exploit, and the rubrics here are themselves LLM-synthesized, so the model is being rewarded against criteria it was also, indirectly, trained to produce. The check-and-correct loop with reference answers helps, but I would run a rubric-gaming probe before trusting the RL gains. Third, the 4B model is text-only in the multimodal cases, using an auxiliary vision policy for view image, and the paper should be read as a text-agent result with a vision assist rather than a native multimodal agent.

Bottom line: this is a clean, reproducible data recipe for small productivity agents, and the real-file grounding is a defensible answer to the synthetic-files-everything trend. If you are training domain agents on messy real documents, the three-stage pipeline of corpus-mined workflows, verified real attachments, and rubric-scored RL is the template to replicate.
