EvoMemState, Evolving Memory State for Personal Agents, from Xiamen University, Nanyang Technological University, the University of British Columbia, the University of Waterloo, and Jilin University. The first three authors are Zhishang Xiang, Yunbo Tang, and Zhongqiao Liu. The paper argues that the memory subsystem of a personal assistant agent is organized around the wrong primitive. Current systems, from MemGPT and Mem0 to MemoryBank, store memory as a pile of independent facts, and the paper's claim is that a fact by itself is not enough. You need to know whether the fact is still true, what scope it applies to, what it conflicts with, and whether it is even relevant to the request in front of you. Those things, the paper says, are states, not facts, and the system should maintain them explicitly.

The motivating failure mode is concrete. A user says last year that they moved from Chicago to Seattle, and a year later that the move is complete. A fact-centric store keeps both records, or keeps the newest one, but either way the agent has to re-derive, at answer time, that the Seattle fact supersedes the Chicago fact, that the move is in the past, and that a question about current commute times should use Seattle. If the two facts are retrieved but their relationship is left implicit, the agent can confidently answer from the stale record, or it can see both and have no principled way to pick. The paper frames this as the difference between a memory-centric paradigm, where memory is a set of facts that get retrieved, and a state-centric paradigm, where each memory is a fact plus a state describing how that fact currently holds and how it should be used.

The framework has three components. The first is Ontology-Guided Memory State Induction. Starting from an empty personal ontology, a graph of entities, attributes, and relations, the system processes the dialogue history incrementally and induces two things. Persistent Facts, the atomic factual records, and Relational States, which track for each fact its validity, its scope, and its evolving relations to other facts, including updates, constraints, and conflicts. The key design choice is that the original records are preserved, not merged into a summary. Merging into a summary is what a lot of memory systems do, and the paper's point is that a summary loses the historical information and hides the conflicts. The ontology construction is iterative, each new chunk of history is incorporated into the graph and the relations are revised, so the relational states evolve as the user's life does. That is the Evo in the name.

The second component is the RL-Based State Evolution, and this is the part that is more unusual. The relational state tells you how the facts hold, but not how to use them for this request. The same memory can serve different purposes across requests, so validity and relations alone do not determine applicability. EvoMemState adds a Reasoning State, a short piece of text generated per request that specifies how the retrieved facts should be applied, their role, and their priority for the current question. The policy that generates these states is a separate small model, initialized from Qwen3-4B-Instruct and trained with group relative policy optimization, GRPO. The reward is interesting because it is relative. For each training instance, the policy samples a group of candidate reasoning states. A frozen personal agent is then run on the request with the retrieved memory evidence plus each candidate state, and the score of that run is compared to the score of the same agent run on the same evidence with no state at all. The reward for a candidate is the difference. A positive reward means the candidate state improved how the agent used the memory, a negative reward means it distorted or weakened the evidence. So the policy is trained to produce states that are, by direct measurement, better than not having a state, and it is explicitly penalized for states that make the agent worse. That is a clean reward design, and it sidesteps the usual problem of training a memory system without a direct signal for whether the memory helped.

The third component is State-Aware Reasoning at inference time. Given a request, the system retrieves semantically similar persistent facts as seeds, then expands each seed by traversing the stored memory relations in both directions, so a retrieved fact pulls in the facts that updated it, constrained it, or conflict with it. Duplicates are dropped. Then the learned policy generates the reasoning state from the request, the retrieved facts, and their relational states, and the personal agent answers grounded in both states. The traversal is the piece that makes the retrieval state-aware. It is not nearest-neighbor similarity over facts, it is similarity over facts plus a relation walk, which is what lets the system surface a stale fact together with the fact that supersedes it.

The evaluation covers four benchmarks. MemSyco-Bench and MemTrapBench measure how a personal agent uses historical memory, including preference updates, evidence priority, and the effects of memory on reasoning. LoCoMo and LoCoMo-Refined measure long-term conversational recall and reasoning across sessions. The baselines are nine memory systems, NaiveRAG, MemGPT, MemoryBank, Mem0, LightMem, A-MEM, Supermemory, SimpleMem, and PGMem. The offline memory construction uses DeepSeek-V4-Flash, and the online response models are Qwen3-8B and GPT-4o-mini, with the state evolution policy the Qwen3-4B model trained with GRPO.

The headline numbers. On MemSyco-Bench, EvoMemState reaches fifty-seven point six percent accuracy with Qwen3-8B and fifty-eight point nine with GPT-4o-mini, beating the strongest baselines by twelve point two and five point nine percent respectively. It gets the best when-to-use and how-to-use accuracy, the lowest rate of inappropriate reliance on historical memory, and the highest correct-use rate with the Qwen3-8B model. On the long-term recall side, the complete retrieval rate, the fraction of questions for which all the required evidence is retrieved, is eighty-five point six percent on LoCoMo-Refined, comparable to the best baseline. But the accuracy on those complete-retrieval questions, the metric that isolates memory use from retrieval, is seventy point eight on LoCoMo-Refined and sixty-eight point five on MemSyco, beating the strongest baselines by eleven point five and thirty-one point two percent respectively. That last number is the one that carries the paper. The retrieval is on par, but once all the evidence is on the table, the state-centric system uses it far more correctly. The paper's observation is that EvoMemState improves when and how memory is used, not just whether it is retrieved, which is exactly the gap the state-centric framing was built for.

A skeptical read. The gains are real and the reward design is the strongest part, because measuring the value of a state by its direct effect on a frozen agent is a much better signal than a proxy like retrieval similarity. What I would want to see before trusting this at scale is the cost accounting. The system now runs an ontology induction pass, a relation traversal, and a GRPO-trained policy that generates a reasoning state per request, on top of whatever the base agent does. The paper reports accuracy, but the latency and token overhead of the state generation, particularly the group sampling during training, is the number that determines whether this is deployable for a personal assistant that has to respond in a couple of seconds. The second thing is the human review in the benchmarks. LoCoMo-Refined and the other memory-use suites are small, carefully constructed sets, and a twelve point gain on a small suite is encouraging but not the same as a twelve point gain on a long, noisy, multi-year dialogue history that no benchmark really captures. The relation traversal is also where the system is most fragile in practice, because the quality of the induced ontology bounds the quality of the traversal, and an ontology that misses a relation means the traversal cannot recover the conflict. The paper preserves the original facts, which is the right call, but it does not fully address how the ontology itself is corrected when it is wrong.

The bottom line. EvoMemState is a clean argument that personal-agent memory needs explicit relational and applicability states on top of the facts, and the relative-reward GRPO training for the reasoning state is a genuinely better supervision signal than the proxies most memory systems use. The retrieval-on-par, accuracy-much-higher result is the one to hold onto, because it isolates the contribution of using memory correctly from the contribution of retrieving it.
