Agent-Editing World Model, Rethinking World Modeling for LLM Agents. The first three authors are Shuang Sun, Guoxin Chen, and Fanzhe Meng, all from the Gaoling School of Artificial Intelligence at Renmin University of China, with the senior authors being Wayne Xin Zhao, Hongteng Xu, and Ji-Rong Wen, the last two being long-time figures in information retrieval and machine learning.

The premise of this paper is a reframe of what a world model should actually model for an LLM agent. The standard approach in the literature is to have the world model predict what the environment will observe, essentially simulate the next tool output, the next terminal readout, the next webpage. The authors argue this is the wrong target. Tool responses are high-entropy and execution-dependent, so reconstructing them accurately is expensive, and when the real tool is sitting right there and can just be called, the predicted observation adds little value on top of the ground-truth one. What actually matters, they argue, is whether the agent's next reasoning step and action will move the task forward, or whether it is a noisy detour that will have to be walked back later. That is a different modeling problem, and it is what the Agent-Editing World Model, or AEWM, is built to answer.

The paper names the specific failure mode it is targeting: task-state contamination. In a long agent trace, the history accumulates unsupported assumptions, outdated plans, and reasoning that was reasonable at step ten but is wrong at step forty. The model keeps that contaminated context in its window, and it keeps conditioning on it, so the bad state persists and quietly distorts every subsequent decision. Existing world models that critique or score the trajectory do not fix this, because they leave the contaminated text in the context; they just add a comment about it. AEWM's move is to edit the state itself.

The system has two coupled capabilities, both trained as part of one model. The first is an Action Judge, which takes a reasoning-and-action step and classifies it into one of three buckets: Critical, where the step is on the right track and should be kept; Exploratory, where the step is a reasonable probe but not yet verified; and Noisy, where the step is a detour, a hallucination, or a stale plan that should be removed. The second is State Revision, which, given the observed history and a flagged noisy continuation, rewrites that continuation into a cleaned version that is consistent with what the environment actually showed. The key point is that the revision is grounded in the same observed history, not in the model's free generation, so it is an edit of the record, not a new guess.

There is a subtlety in why these two pieces have to travel together. A critic that only scores the trajectory, which is what most world-model-in-the-loop systems do, leaves the contaminated text in the context window, and a language model conditioned on that text will keep doing what the text suggests, critique or not. The model is not reasoning about the score; it is reasoning about the history. So the unit of intervention has to be the history itself. EditAct is the inference-time system that wires the two capabilities in: the agent runs a step, the Action Judge classifies it, and if the step is Noisy, State Revision rewrites that segment of the working context before the agent takes its next action. The agent then continues from the edited state, which means the contamination is removed from the conditioning rather than annotated alongside it. That is the difference between telling the model its plan is wrong and actually deleting the wrong plan from what it sees.

The training is cross-domain, which is a notable design choice. They mid-train on roughly fifty-two billion tokens of trajectories across three domains, Search, Terminal, and Software Engineering, and then do supervised fine-tuning with about sixty thousand examples each for Action Judge and State Revision. The Action Judge is evaluated on a benchmark of its own, and it reaches a macro F-one of seventy point five percent, which the authors report is ten point six points above the strongest frontier baseline they test. That baseline set is the right one to compare against, and it is worth naming: they line up Gemini 3 Pro, GLM 5.2, Qwen3.7 Max, GPT 5.5, and DeepSeek V4 Pro as prompt-only judges on the same benchmark, and AEWM beats the best of them by double digits on a task where the frontier models are already in the low-to-mid fifties. A prompt-only frontier model asked to classify an agent step is doing the job with no domain training, which is a strong baseline, and clearing it by ten point six points on a three-class task is a real result, not a leaderboard rounding error.

The downstream result is where the paper earns its keep. They wrap AEWM in an inference-time system called EditAct, which runs the agent, has the Action Judge score each step, has State Revision edit the noisy steps, and then lets the agent continue from the cleaned state. The six benchmarks span the three domains: BrowseComp and DeepSearchQA for search, Terminal-Bench 2.0 for terminal work, and Doc2Repo, NL2Repo, and SWE-Bench Pro for software engineering. On a thirty-five billion parameter Qwen3.5 MoE backbone, EditAct improves every single one: BrowseComp goes from forty point nine to forty-eight point one, DeepSearchQA from sixty-nine point four to seventy-eight point six, Terminal-Bench 2.0 from thirty-seven point one to forty-eight point three, Doc2Repo from forty-two point eight to forty-eight point nine, NL2Repo from twenty-two point four to twenty-five point three, and SWE-Bench Pro from forty point six to forty-three point eight. The three point two to six point seven point average improvement the abstract reports is the range across three different agent backbones, and the gains hold in all of them, which is the more important fact, because it says the editing layer is a drop-in component rather than something tuned to one model. They also run a follow-on experiment, AEWM-RFT, where they rejection-sample fine-tune on verified EditAct trajectories, and even without the online AEWM guidance at inference time, that fine-tuned model beats the analogous Self-RFT baseline by two point two to two point six points across the three domains. That last result is the more durable contribution, because it shows the value of the editing process transfers into the weights rather than only living at inference time. The RFT result also answers a question a skeptic would ask first: is EditAct just an expensive test-time patch that vanishes when you stop running the judge? No. The rejection-sampled fine-tune bakes the editing behavior into the model, and it still clears the Self-RFT baseline that does the same rejection sampling without the AEWM verification step, which means the verification step, not the fine-tune, is what is doing the work.

The honest caveats. The Action Judge is only as good as its three-way taxonomy, and the paper does not fully stress-test what happens when a step is genuinely ambiguous between Critical and Exploratory, which is probably most real steps. The edit step, while grounded in observed history, is still a generative rewrite, and a bad edit can introduce a new error that the original noisy step did not have, which the paper acknowledges but does not quantify. And the three domains, while diverse, are all text-heavy, tool-using agent settings, so the transfer to, say, embodied or multimodal agents is an open question. The reframe itself, though, is the more interesting contribution. If the goal of a world model for an agent is to make the next decision better, then modeling task progress rather than tool output is a defensible and, in this paper's results, measurably useful target, and the released model plus the Action Judge benchmark give the field a baseline to build on.
