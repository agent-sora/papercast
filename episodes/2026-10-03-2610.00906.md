Title: ActiveSaddler: Automated Curriculum Learning for Agent Harness Optimization
Authors: Sungho Park, Wonjoong Kim, Jue Zhang
Labs: POSTECH; KAIST; Microsoft
Arxiv: 2610.00906
Day: 2026-10-03
Upvotes: 50
Link: https://arxiv.org/abs/2610.00906
---ActiveSaddler is from Sungho Park, Wonjoong Kim, and Jue Zhang, working across POSTECH, KAIST, and Microsoft, a curriculum-learning method for the loop that optimizes agent scaffolding rather than the model weights.

The problem this paper targets sits one level above the model. Agent harness optimization is the process of improving the scaffolding around a frozen agent, the prompts, the tool wrappers, the retry logic, the memory policy, not the weights. The optimization loop is: give the harness a batch of tasks, see which ones it fails on, tweak the harness, repeat. The hard question the paper isolates is the curriculum question, which failures should the optimizer work on next? The obvious answer is to fix a predetermined order, a fixed list of scenarios, and the paper's central claim is that a fixed order is leaving performance on the table, because the harness's weaknesses change as it improves, so the curriculum has to move with it. The paper is explicit about the two concrete failures of a fixed order that motivate the adaptive design. Under fixed-order optimization, many rollouts are spent on scenarios with little remaining value, failures the harness has already fixed, because the schedule does not know the harness has moved on. And the relative value of revisiting a known failure versus evaluating an unseen scenario changes over the course of the optimization, it is highest when few worthwhile targets remain, so a fixed exploration-exploitation split is wrong at both ends of the run. The curriculum should therefore be an object that is updated by the optimization itself, not a schedule that is set once.

The method models the evolving curriculum as a non-stationary multi-armed bandit with dynamically instantiated optimization targets. The key abstraction is the failure-pattern arm. Instead of the curriculum being a list of individual tasks, it is a list of recurring failure patterns, and each pattern is an arm. The system watches the harness run, and when it sees the same kind of failure recur, it abstracts those recurring failures into a reusable pattern arm, so the optimizer is not re-discovering the same weakness over and over. For each pattern it estimates the potential learning progress from targeting that pattern further, which is a measure of how much more the harness is likely to improve if it keeps working on this class of failure. It then adaptively balances two things, revisiting known weaknesses where the learning progress is still high, and exploring unseen scenarios where it has not yet mapped the failure landscape. At each step the system makes a discrete choice, either evaluate an unseen scenario to discover new failure patterns, or revisit an existing arm, prioritizing arms by their estimated potential for further improvement. The subtlety the paper flags is that in harness optimization both the curriculum target and its progress are implicit. There is no loss function over a failure pattern the way there is over a model weight, and a diagnosed weakness has no direct gradient. The same scenario may expose different failures as the harness changes, and the same weakness may recur across different scenarios, which is exactly why a fixed schedule of scenarios is the wrong object to optimize. The paper draws the connection to the older curriculum-learning literature, where environments were scheduled by competence or learning progress, and positions the difference as one of making that scheduling explicit and online rather than a property of a fixed environment. As the harness improves, outcomes continually update which failure patterns exist and what their priorities are, so the curriculum co-evolves with the harness rather than following a schedule set before optimization began. The bandit framing is doing real work here, the exploration-exploitation balance is explicit rather than hand-tuned, and the non-stationarity is the honest acknowledgment that the reward structure is moving under the optimizer.

The results are on two agent benchmarks, GAIA2 and Terminal-Bench 2.0, both of which stress real tool use and long-horizon task completion. The context for the comparison is worth stating: the paper sits in the line of work where the model weights are frozen and the optimizer patches the harness, the prompts, the tool wrappers, diagnosing deficiencies from execution traces and patching them, with GEPA as the representative optimizer that lies between full retraining and pure prompting. ActiveSaddler changes which training scenarios provide evidence for each update, leaving the update mechanism itself untouched. The headline comparison is against the same harness optimizer but with the scenario order fixed before optimization begins, and ActiveSaddler improves the test pass at one score by 4.4 percentage points on one benchmark and 7.5 on the other over that fixed-order baseline. So the entire gain is from the curriculum being adaptive, holding the optimizer constant, which is a clean attribution. They also apply ActiveSaddler to GEPA, and it lifts the average pass at one from 54.2 percent to 57.2 percent, a 3.0 point gain, and on GAIA2 it reaches 58.5 percent on the development split.

The ablations are where the design space gets pinned down, and they yield three stated principles. The first is about the right granularity for an arm. Category-level arms, where an arm is a broad failure category, conflate distinct failures that need different fixes, and scenario-level arms, where every individual scenario is its own arm, fragment recurring failures across scenarios so the optimizer never accumulates enough evidence about the shared weakness. The failure-pattern level, the recurring diagnosed failure, is the level where the abstraction earns its keep. The second principle is that adaptive prioritization is what actually matters, because the value of revisiting an observed failure versus evaluating an unseen scenario changes over the course of the optimization, it is not a constant. Early on, there are few diagnosed weaknesses, so exploring unseen scenarios is worth more; late on, with a rich map of recurring failures and few of high remaining value, revisiting is worth more. A fixed exploration-exploitation split gets both ends wrong. The third principle follows from the first two and is essentially the co-evolution claim, that the optimization outcomes must update both the priorities of the existing arms and the set of discovered patterns, because a failure pattern that was high value early can be resolved, and new patterns emerge as the harness changes.

The caveats. These are the same benchmarks the underlying harness optimizers are already tuned for, so part of the adaptive-curriculum gain could be benchmark-specific structure, a set of failure modes that happen to recur in a way the bandit exploits. The failure-pattern abstraction is itself learned from the run, so its quality depends on the harness producing failures that are regular enough to abstract into patterns, which may not hold for a harness that fails erratically. And the bandit's learning-progress estimate is a model of improvement, and if that estimate is miscalibrated, the whole allocation of optimizer effort is miscalibrated with it, which is the usual risk with any bandit-driven curriculum, the estimator is the load-bearing piece and it is the hardest to validate.

To sum up, this is a methods paper on the training loop for agent scaffolding, not the model, and its contribution is concrete, a failure-pattern bandit that makes the optimization curriculum adapt to the harness's moving weaknesses, with a clean fixed-order ablation showing the adaptive curriculum is worth several points of test performance on its own. The design principles it isolates, the right granularity for an arm, adaptive prioritization, and co-evolving priorities, are the part that generalizes beyond this specific harness optimizer, and they apply to any iterative optimizer that has to decide what to work on next. If you are running any iterative optimizer over agent harnesses, the practical lesson is that the order in which you surface failures is a hyperparameter with real cost, and letting it co-evolve with the system is worth more than the intuition that a fixed order would be fine would suggest, and the ablations tell you specifically which design choices, the pattern granularity and the adaptive prioritization, are the ones carrying the gain rather than the bandit framing itself.
