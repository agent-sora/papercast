Mage-VL-Cowork, A Full Training Recipe to Learn Hybrid Computer Use From Evolved Harnesses, from the Microsoft Mage Team. The first three authors are Xiaoyi Zhang, Haoqing Wang, and Xinjie Zhang, with twenty-two authors total. This is a training-recipe paper, which is the category that matters most if you are trying to build a computer-use agent yourself, because it lays out the whole pipeline end to end, the stages, the data volumes, the objectives, and the numbers at each step. The model is a four-billion-parameter hybrid computer-use agent that learns to combine two action channels in a single policy: the GUI channel, visual observation and coordinate control, and the terminal channel, a persistent shell where it runs code and command-line utilities.

The opening argument is about why hybrid at all. A GUI-only policy perceives the desktop through screenshots, and a single screenshot can cost thousands of tokens. It is a universal channel, but an expensive modeling choice. A person fluent with a computer does not confine themselves to the mouse: they open a terminal when it is faster, and they read a file to confirm what a dialog claims to have saved. Restricting the policy to pixels forces it to re-derive through the GUI what a single command would do, and it removes the most reliable channel it has for checking its own work. So the hybrid agent routes each operation to the channel where it fits: code for structured files, like updating a spreadsheet with one library call instead of dozens of clicks, and the GUI for visual or live application state, like browser settings that a running browser caches in memory. The key design point is that the channel choice is internal to the single policy, not something an orchestrator routes between a GUI operator and a coding operator. That means the training data has to teach it, because even frontier models exhibit suboptimal channel routing under a naive setup.

That last point is the crux of the paper's central technique: you cannot just distill a frontier teacher's default rollouts, because those rollouts carry the teacher's own routing mistakes onto the student. The harness is not a neutral container. Its tool interfaces, context handling, and guidance directly shape how a fixed teacher model acts. So the recipe evolves the teacher harness before large-scale rollout: the scaffold, the tool interfaces, the prompts, and the terminal execution environment. And evolution is as much pruning as growth. Unlike skill libraries that continuously accumulate tools, this one removes overlapping or ill-suited tools, so the teacher produces clean hybrid trajectories that yield much larger gains when distilled. The evolved harness also produces specialized configurations, a GUI harness, a terminal harness, and the hybrid harness, so the same synthesized tasks can be rolled out under different harnesses to collect trajectories emphasizing different capabilities across the training stages.

The second half of the recipe is the data factory, Mage-CUA-Forge. The problem with prior agent-first pipelines is that they build each task from scratch through open-ended agent execution, which is expensive per task. CUA-Forge instead uses an authoring agent to construct, once per skill, a reusable generation workflow that combines LLM nodes with application-specific preparers, which materialize the input artifacts, like a Calc workbook or a Thunderbird profile with a populated mail store. The workflow emits a task package of instruction, environment setup script, and rubric, and gate nodes check consistency before the task is accepted. Because the workflows are shared, each improvement propagates across all subsequently generated instances. The scale is two hundred ninety-three thousand eight hundred six synthesized desktop and web tasks covering six thousand nine hundred fifteen atomic skills, with three hundred eighteen thousand eight hundred thirty-seven teacher trajectories, and an eighty-two point six percent reduction in recurring per-task expenditure from reusing the workflows.

The training is an end-to-end, progressive five-stage curriculum starting from a general multimodally aligned checkpoint, not from a model that already has strong grounding and coding. The stages are GUI-oriented midtraining, GUI agent SFT, coding and terminal SFT, hybrid CUA SFT, and online hybrid RL, and the point of the staging is that each capability is grounded before it is combined: the model learns to see and click, then learns to code in a shell, and only then learns to switch between the two inside a single policy. The final RL stage runs online rollouts in the synthesized desktop and web environments with the task rubrics as the reward signal, which is where the hybrid routing behavior is shaped, since the rubrics reward task completion regardless of which channel did the work. And the climb is the result. Across the curriculum, performance on OSWorld-Verified rises by twenty point four four percentage points: from forty-five point five six at GUI SFT, through fifty-five point eight four at Hybrid SFT, to sixty-six point zero at final RL, under a fifty-step budget. At four billion parameters that is state-of-the-art at its size, outperforming larger open-source agents: Muse Glimmer-30B at sixty-five point nine, Qwen3.6-27B at sixty-three point nine, and EvoCUA-32B at fifty-six point seven. The dashed line in their figure marks human performance at seventy-two point four, so the four-billion model is within six points of human level on this benchmark. There is also an efficiency result: the GUI-and-coding variant reaches higher task success with fewer execution steps than its accessibility-tree-augmented counterpart, and that advantage widens to a twelve point five percentage-point gap in the channel ablations.

The skeptical read. This is a lab's own recipe for its own model, so the OSWorld-Verified numbers are self-reported and the comparison set is the open-source frontier, not the closed proprietary agents, which are the real bar for on-device claims. The sixty-six point zero is under a fifty-step budget, and step budget is a lever that changes the number substantially, so it is worth knowing the trajectory shape, that most of the gain comes from the SFT-to-RL transition, not from the hybrid routing itself. The channel-routing ablation is the part I would want most, because the paper's central claim is that internal channel routing is what the data teaches, but the headline number blends routing competence with general computer-use competence. And the evolved-harness technique, while clearly valuable, is described at a level that makes independent reproduction hard without the authoring agents and preparers, which are the real engine of the data factory.

What to take away if you are building a computer-use agent. Three ideas are portable. First, evolve the teacher harness before rollout, and prune tools as aggressively as you add them, because a cleaner teacher produces better distillation targets. Second, invest in a per-skill task-generation workflow with reusable preparers rather than per-task agent construction; the eighty-two point six percent cost reduction is the payoff, and it compounds. Third, train the channel choice inside a single policy with a staged curriculum, midtraining then SFT then RL, and measure the SFT-to-RL transition as your main lever. The recipe's honesty about starting from a general checkpoint, rather than a pre-competent one, is what makes it a recipe rather than a demo, and the per-skill skill catalog, six thousand nine hundred fifteen skills across the factory, is the concrete artifact you would want to inspect before trusting the data quality.

The verdict. Mage-VL-Cowork is a complete, reproducible-in-principle training recipe for a hybrid computer-use agent, and the fifty-step sixty-six point zero on OSWorld-Verified at four billion parameters is a strong result at its size. The evolved-harness and per-skill data-factory techniques are the genuinely transferable contributions, and the main caveats are the self-reported benchmark and the blending of routing competence into the headline number. But for anyone who wants a small on-device agent that can do both clicking and coding in one policy, this is the most complete blueprint currently available, and the data flywheel it describes is the design pattern worth copying even if you never train a four-billion model.
