SkillZip: Contract-Preserving Graph Compression for Scalable Agent Skill Libraries, by Xingyu Tan, Xiaoyang Wang, and Qing Liu, from UNSW Sydney and CSIRO. The problem will be familiar to anyone running a skill library at scale: skills are retrieved as whole packages, compressed as plain text, and turned into execution graphs only after retrieval, and that unit mismatch is exactly where things fail. Whole-skill exposure wastes context on irrelevant sections, text summarization can silently drop a precondition or a verifier hook, and task-time graph compilation never improves the library itself. SkillZip's answer is to make the section-level procedural graph the persistent storage format, then compress it in a way that provably keeps procedures executable.

The representation comes first. Each skill package is decomposed by Sec2Graph into typed section nodes with nine execution roles: Intent, Trigger, Input, Precondition, Operation, Resource, Failure, Verifier, Output. Segmentation uses headings, lists, code blocks, warnings, argument descriptions, tool references, and tests as boundary cues, with a model-assisted parser refining when cues run out, always preserving source pointers back to the original text; role assignment is semantic, so in a tabular skill infer-the-delimiter is an Operation while verify-row-counts-unchanged is a Verifier regardless of file position. Each node carries input-output signatures, resources, guard and verifier conditions, and provenance. Edges come in four kinds: typed dependencies such as requires, binds, uses-resource, verifies, and repairs; weak-order edges for local sequence inside a skill; skill-membership edges; and equivalence links connecting compatible occurrences to shared canonical prototypes that expose cross-skill reuse, like tabular ingestion shared by cleaning, pivoting, and plotting skills, without erasing occurrence identity or membership. A skill becomes a subgraph rooted at an intent or trigger node, terminating at a verified output node. The triple of interface aspects covering typed I-O and resource bindings, execution aspects covering preconditions, guards, effects, and failure handling, and verification aspects covering success conditions and verifier hooks forms what the paper calls the procedural contract.

MotifZip does the compression. Instead of unrestricted frequent-subgraph mining, which happily merges two different load-data routines with incompatible verifiers, candidates grow only from interface-compatible buckets keyed on role signature, resource family, and I-O shape, with semantic similarity consulted only after the structural compatibility check. Occurrence support counts non-conflicting matches over source occurrences, never prototypes, where two occurrences conflict if they share an internal section node or need incompatible port reconnections. A motif becomes a macro only after three checks pass: stable interfaces across all occurrences, dependency closure meaning every dependency is internal or explicitly exposed as a port, and verifier reachability meaning every state-changing operation keeps a check inside the macro contract or reachable from its output. Accepted motifs become production rules in a typed attributed graph grammar, scored by a description-length gain formula rewarding frequency and cross-skill reuse while penalizing boundary cuts and execution risk, applied greedily in descending gain with overlapping rewrites skipped. Crucially this is a reversible rewrite, not a summary: each macro stores ports, contracts, occurrence mappings, verifier hooks, rendering levels, and source pointers, and expansion restores the exact original subgraph. Proposition 1 proves compositional lifting: compress-then-expand yields an isomorphism preserving typed external dependencies and operation-to-verifier reachability, and the authors are explicit the guarantee is structural rather than semantic.

PathHydrate handles runtime. A query becomes a structured task object with goal, expected outputs, required capabilities, visible inputs, executor profile, and ordered subgoals. Seeds are matched against section nodes under both the subgoal view and the raw-query view, taking the max cosine score per node, then fused with two skill-level rankings, one from skill descriptions and one from the best section match inside each skill, through reciprocal rank fusion so fine-grained precision does not scatter across unrelated packages. Constrained subgraph search minimizes token cost plus section count plus estimated future expansion cost minus anchor coverage, subject to anchor coverage, dependency closure, verifier reachability, and a token budget whose default is 3,000 tokens; at runtime it adds low-cost connectors until required roles close or the next addition would exceed budget. Scaffold repair walks backward from operations to recover Input, Precondition, and Resource sections, forward to recover Failure, Verifier, and Output sections; if no verifier-reachable context fits the budget it falls back to the smallest skill-level bundle covering the anchors. Context filling is sufficiency-gated rather than budget-seeking: once anchors are covered, dependencies closed, and a verifier reachable, it stops spending, leaving unused budget unspent on extra procedural text. Macros hydrate progressively through four levels, name, contract, outline, full source, expanding automatically whenever a needed guard, verifier, or source pointer is not exposed. The rendered context includes intent, bound inputs, preconditions, hydrated operations, resources, guards, failure handlers, verifiers, and source expansion pointers, and every run writes a hydration log recording selected sections, macro levels, token cost, late expansions, and verifier coverage, which feeds ReZip. ReZip closes the loop: new skills reuse compatible macros immediately while unmatched regions enter a residual buffer, residual motifs get promoted only after minimum cross-skill support with positive compression gain and valid contracts, and macros accumulating expansions, verifier failures, or downstream repair cost get their hydration level raised first, then split into narrower contract-compatible rules or retired to source sections based on execution evidence.

Numbers. SkillsBench and ALFWorld, two backbones, four baselines including whole-skill loading, embedding retrieval, GoS, and SkillDAG, with all 87 tasks evaluated under the 1,000-skill setting. With MiniMax-M2.7: 33.3 reward on SkillsBench and 79.3 success on ALFWorld, up 6.0 and 12.2 points over SkillDAG. With gpt-5.2-codex: 43.0 and 96.4, gains of 6.2 and 2.8 against baselines already near ceiling. Retrieval moves similarly, Ret-at-1 from 66.7 to 73.6 and Ret-at-5 from 78.2 to 92.0 on SkillsBench, with MRR gains confirming the right source moves toward the top rather than entering the candidate set somewhere. Efficiency counters on matched runs: 47 percent less cumulative prompt processing, 21.7 percent fewer tool calls, 18.7 percent less uncached prompt input, 21.1 percent lower end-to-end latency versus SkillDAG.

The compression table is the honest core. Text compression reaches the same 3.46 ratio as SkillZip but drops dependency preservation to 65.0 and verifier reachability to 60.0, needs recovery from originals on 45 percent of queries, and loses 7.8 reward. Generic graph grammar gets 2.91 ratio but also loses structure. Removing SkillZip's own contract checks yields 3.78 ratio and worse everything else, direct evidence unsafe merges damage execution. SkillZip itself holds 99.2 dependency preservation and 98.7 verifier reachability at 3.46 times compression, a 71 percent cut in active storage, cutting recovery rate to 14.8 percent while beating even the raw uncompressed section graph on reward, 33.3 versus 31.0. Ablations rank the components: dropping section-level nodes costs 5.4 reward and inflates context 59.9 percent; removing MotifZip leaves fidelity perfect but context grows 52.9 percent; removing dependency closure sinks DPR to 82.3; removing verifier constraints sinks VR to 76.4; disabling adaptive hydration burns a third more tokens. Contract extraction quality was checked against human annotation at 91.6 macro-F1 and 84.6 exact match, staying robust under 10 percent field corruption. Scaling holds from 200 to 100,000 skills, where the Ret-at-1 advantage widens from 6.2 to 23.3 points with 248 millisecond online retrieval latency, and offline construction over 4.77 million section nodes completes in 178 seconds.

Limitations, plainly: evaluation covers two benchmarks and technical-plus-embodied tasks, both tabular-flavored, so generalization to your domain is untested. The pipeline leans on an LLM parser for segmentation, and the paper reports association between technique and outcome without isolating parser error contribution end to end. Baseline comparisons share one implementation stack; no ablation over the gain-formula weights alpha, lambda, mu. And the structural guarantee is not semantic correctness: it preserves recorded contracts, not the truth of any verifier. Bottom line: if your agent stack retrieves skills as monolithic packages, the section-graph-plus-contract-checks pattern is sound engineering you can adopt incrementally, and the 3.46-times compression with near-total fidelity numbers are the strongest published evidence that executable structure survives aggressive abstraction. Budget for building the role taxonomy and contract extractor for your own skill format before expecting comparable results.
