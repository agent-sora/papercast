## AutoDesign: Optimizing the Harness That Builds the Artifact

First, "AutoDesign," a framework for meta-harness optimization. The setting: turning multimodal input into a structured output, like generating an academic poster from a paper, is really a long-horizon agentic process. Existing harnesses for this are static — designed once by hand and never improved. AutoDesign adds a meta-harness optimizer that guides a code agent to recursively rewrite its own harness based on rollout feedback, aligned with human design priors.

The numbers are striking. On their PosterBench main track, AutoDesign scores seventy-eight point three, beating Claude Design, the closed-source commercial system, by seven and a half points. Across seven controlled configurations, adding the learned harness lifts the average score from fifty-five to sixty-seven. In a fully autonomous loop it executed two hundred and fifty-three tool calls and eleven editing rounds in forty minutes, for under three dollars, reaching average conference-poster quality in blind human evaluation.

For a staff engineer, the transferable idea is the loop shape itself: treat your orchestration code as the learnable artifact, roll out, measure with a fixed verifier, patch the code, repeat — all while the expensive model stays frozen. That is cheap iteration on the part of your stack that changes most, instead of fine-tuning the part that changes least.

## SKILLER: Reinforcement Learning That Writes Skills in Plain English

Next, "SKILLER." Agent skills — those packaged procedural instructions that constrain a model's behaviour — work brilliantly, but writing good ones by hand is expensive, and running strong closed models to execute them is even more expensive. SKILLER asks: can reinforcement learning automatically write skills tuned for small, cheap, locally hosted models?

Their trick is to move the whole RL loop into natural language. A strong model plays actor and critic. The small-model agent system is the environment. And every reward signal is propagated as language — critiques and revisions of the skill document — rather than gradient updates. On five benchmarks, with nine-billion and four-billion parameter Qwen models, SKILLER-written skills beat four competing skill-generation methods by up to twenty percentage points, and on single-skill tasks the small models essentially match strong closed-source systems.

Why this matters practically: if you serve skills to small open models on consumer GPUs, this is a path to get closed-model quality at open-model cost, and the artifact you ship is just text — auditable, versionable, diffable. The lesson generalizes beyond skills: when your lever is a prompt or policy document, language-level RL is a surprisingly effective optimizer.

## LycheeMemory V2: Cheaper Long-Term Memory by Batching

Third, "LycheeMemory V2," about long-term memory for agents. Most memory systems consolidate eagerly: after every single exchange, they invoke a model to extract, summarize, or update memories. That design makes cost grow with conversation length, and the obvious fixes trade accuracy away.

LycheeMemory replaces turn-level consolidation with segment-level consolidation. Multiple exchanges accumulate into a segment; semantic boundary detection decides where segments end; each finalized segment becomes context-independent, typed memory records stored under lightweight structured indexes for query-planned retrieval. On long-conversation benchmarks it hits eighty-nine percent on LoCoMo and ninety-two percent on LongMemEval-S, while cutting memory construction tokens by eighty-six percent compared with a strong baseline — without increasing query-time cost.

The insight worth stealing is granularity as a first-class knob. The accuracy-versus-cost trade-off in agent memory depends not just on what you retain but on the granularity at which you consolidate. If your agent's memory bill is growing linearly with usage, batching consolidation at semantic boundaries is the cheapest fix on the table.

## DarwinX: Evolving a Population of Agent Harnesses

Fourth, "DarwinX," which pushes harness self-improvement from single-lineage hill climbing to something that looks like real natural selection. Prior self-improvement loops edit one harness along one lineage; local wins often regress other tasks. DarwinX maintains a population of harnesses with the model frozen. A preserve-and-extend contract admits only variants that extend coverage without regressing anything already mastered. An archive keeps alternative lineages around for recombination. Fitness comes strictly from each benchmark's own verifier — no gold solutions, no hand-picked winners.

Results across four benchmarks: one evolution loop adds about seventeen points on average. Terminal-Bench rises to eighty-three percent on a matched base. WebArena pass-at-one goes from forty-three point five to ninety-three percent, audit-clean. And a harness evolved purely on terminal benchmarks transfers unchanged to SWE-bench Verified — evidence it evolved general competence rather than benchmark-specific tricks.

The engineering moral: single-lineage self-improvement overfits the path it happened to take. Keeping a population, a regression-proof admission contract, and recombination is what makes automated improvement durable. If you build any automated improvement loop — agents, prompts, CI heuristics — those three ingredients are the difference between a demo and a system.

## Knowing When to Quit: Teaching Models to Refuse Futile Reasoning

Fifth, "Knowing When to Quit." LLMs facing beyond-capability tasks generate computationally expensive, semantically void reasoning — and worse, plausible-sounding derivations containing subtle errors that mislead users. The authors characterize this futile-reasoning phenomenon systematically and find the dominant failure mode is specious reasoning: output that looks superficially valid but contains quiet mistakes, escalating sharply with task difficulty.

Their fix, CaRL, capability-aligned reinforcement learning, shapes rewards so that honest refusal of futile reasoning beats confident waffle, plus hindsight augmentation that converts observed failures into refusal supervision. The result: substantially less futile reasoning with performance preserved across difficulty levels.

This is rare and valuable: a paper treating refusal as a first-class trained behaviour rather than a safety afterthought. For anyone shipping reasoning products, the calibration question — does the model know the difference between hard-but-solvable and impossible-for-it — is a reliability problem you own. Reward shaping that pays for honest surrender is the mechanism this paper validates.

## When Rhetoric Reward-Hacks AI Reviewers

Finally, a warning shot for everyone using LLMs as judges. This paper asks how rhetorical choices — with the scientific content held constant — sway AI peer reviewers. They built forty-two hundred full manuscripts derived from a hundred and twenty anonymized conference submissions, rewrote them along six rhetorical dimensions in opposing directions, and ran five LLM reviewers.

Findings: rhetorical sensitivity is structured, not uniform. Evidence framing and novelty stance swing assessments the most; scope framing forms a weaker second tier. Score movement depends strongly on where the reviewer started: lower scores tend to rise under polish, higher ones tend to fall. Elaborate defences don't reliably help — joint rewriting is strongly rewriter-dependent, and repeated rewriting yields diminishing returns. Strict review protocols lowered mean scores slightly without reducing sensitivity at all.

If you use LLM judges anywhere — code review, support triage, content grading — assume the prose wrapper moves scores, and defend with structure: extract claims into a fixed schema before judging, randomize framing, and audit judge drift the way you audit model drift.
