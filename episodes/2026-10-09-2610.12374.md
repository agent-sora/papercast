"AgentGarten: code worlds for evolving agents," a technical report from the MirroS team, with the first three authors Jiawei Chi, Shangchen Miao, and Zhiyuan Shi, from MirroS, Tsinghua University, and Peking University. This is a framework paper, and the pitch is a clean one. Agents learn by acting in environments, but the environments have to be both faithful, with consistent state and rules that you can actually inspect, and realistic, with observations that look like the real world. Existing systems give you one or the other, and this paper argues you can have both by splitting the job: real simulators and game engines own the state and the rules, and a single shared neural renderer owns the pixels.

The trade-off they start from is real. Simulators and game engines give you explicit state and programmable interaction rules, which is exactly what you want for a controllable training environment, but expanding their visual diversity means a lot of 3D asset creation and complex rendering pipelines, so new environments are expensive to build. Video world models, on the other hand, synthesize rich, interactive visual observations from data, but in those models the task-relevant state and the physical transition rules are implicit inside the generated history and the learned representations, so you cannot directly inspect, edit, or test the environment's behavior. AgentGarten's answer is a code world: a scene program runs in a simulator or game engine that maintains persistent state and executes explicit rules, and a shared neural renderer synthesizes the visual observations from structured conditions that the engine exports through a unified interface.

The formulation is worth stating precisely, because it is the whole architectural bet. A code world is a scene program, an engine that executes it, and a neural renderer. The engine takes the scene state, which includes object poses, articulations, and task variables, the camera pose, and the agent actions, and it updates the state and captures a structured condition from the camera. The renderer then generates the next visual observation from the visual history, the accumulated conditions, an appearance reference, and a text description. The key property is that the state transition takes no rendered observation as input. The renderer can only influence the state through the actions the agent selects. That means rendering errors cannot accumulate into the state. You can take a recorded state trajectory and re-render it under a different appearance or a different camera without changing the underlying events. That is something a pure video world model simply cannot do, because in that world the state lives inside the generated pixels.

The structured conditions are colorized depth maps or surface normals, chosen because both can be estimated from real video or rendered directly by an engine, and because their three-channel representation lets you reuse the pretrained video encoder and Transformer. For real videos they estimate depth with a tool called ViPE using Depth Anything 3 as its backend, and normals with NormalCrafter. Simulated scenes supply the maps straight from geometry, with no detailed materials or textures required. The renderer backbone starts from Cosmos 3 Nano, whose understanding and generation towers they separate, with a frozen Wan video autoencoder mapping RGB and geometry into latents. They convert a bidirectional model into block-causal autoregressive generation, and the whole renderer runs in real time on a single GPU.

The training method they name, Adversarial Forcing, is the technically interesting part. It distills the teacher-forced model into a few-step renderer trained on its own rollouts, and it has three components. The first is distribution matching, in the Self Forcing style, where the autoregressive student generates each block in a few denoising steps conditioned on its own preceding outputs, and a frozen teacher plus an auxiliary fake-score model score the resulting clip. The second, and the novelty, is exact replay. In standard Self Forcing, completed blocks are written into a detached key-value cache, so later losses supervise prediction from that cache but never the history-prefill computation that produced the cache. To get gradients back to the parameters that write history, without the memory cost of a fully differentiable rollout, they use a two-pass scheme. A no-gradient rollout records each block's input and its clean output, and a differentiable replay recomputes the history encodings inside the graph. The crucial detail is that they preserve the rollout's execution structure: attention runs block by block with scaled dot-product attention, using the same key-value order and the same call shapes, so the recomputation is bitwise-identical to the original sampling. They specifically contrast this with an alternative, SGF-style replay that uses one full-sequence FlexAttention call, which changes the tensor shapes and reduction order and can diverge numerically in finite precision. The third component is a real-data adversarial objective, using a relativistic R3GAN pairing, with an exact R1 and R2 regularization for the discriminator that avoids the double-backward pass through fused attention kernels like FlashAttention, which those kernels do not support. They exploit the fact that the backbone is frozen to compute the exact penalty and its exact gradient with a single vector-Jacobian product and a single Jacobian-vector product, never materializing the full Jacobian.

Now the empirical study, because that is what I would weight. They run pretrained foundation-model agents through rounds of interaction, where the agents perceive the world strictly through the rendered observations, diagnose failures, and distill the key insights into written playbooks that the next round's agents inherit. Each round is several games over sampled layouts and seeds, and after each round each role reviews its own action programs and the visual evidence it was allowed to see, identifies failures, and adds skill files to its playbook. The next round starts in fresh conversations from the task file and every earlier playbook. The headline result is the learning-efficiency gap against conventional reinforcement learning. In a hide-and-seek setting, the strategy self-play reinforcement-learning baseline needed roughly twenty-five million training episodes before hiders built shelters, and on the order of a hundred million before seekers used ramps to enter shelters. The AgentGarten agents, working only through rendered observations and reflective playbooks, had hiders building shelters within four rounds and seekers using ramps within ten. That is a several-orders-of-magnitude gap in samples, and it is the number that makes the approach compelling. They also show the same reflective loop improving outcomes across rounds in four additional, diverse worlds: a companion-dog task, a one-lane bridge crossing, a herding task, and a quarry-loader task, with round-by-round score improvements listed in the results.

Let me be honest about what I would trust and what I would re-verify. What I would trust is the architectural separation, because it is principled. Giving the simulator ownership of state and rules while delegating only the appearance to a neural renderer is exactly the right way to get inspectable, editable dynamics with realistic pixels, and the fact that rendering errors do not accumulate into state is a genuine, verifiable advantage over a pure video world model. The exact-replay and exact-R1R2 results are the kind of careful numerical work that tells you the team actually ran this and cared about reproducibility. What I would re-verify before betting on it is the scale of the empirical claim. The learning-efficiency comparison is a headline number, but the RL baseline and the reflective-playbook baseline are quite different learning regimes, and "four rounds" is a small absolute number built on a handful of games and a handful of rounds, so I would want to see the variance across seeds and a larger set of worlds before I treated that orders-of-magnitude gap as a stable property rather than a demonstration. The engineering gotchas are the practical ones. This is a real-time neural renderer on a single GPU, but it is still a diffusion-style video model running in an interaction loop, so the per-step latency budget is tight and you are trading a lot of engineering against the cost of authoring 3D assets. Building new code worlds is delegated to a coding agent that calls perception and generation models as tools and then repairs the scene through probe cameras and collision and occlusion checks, which is promising but is itself an agentic pipeline you have to get right.

Here is the bottom line. AgentGarten is a credible framework for building interactive, visually realistic environments where the state and rules stay programmable and inspectable while a shared neural renderer supplies the pixels, and it pairs that with a strong empirical signal that reflective, playbook-based agents learn these code worlds in a handful of rounds where a conventional reinforcement-learning baseline needs millions of episodes. If you are trying to scale agent training environments without hand-authoring a 3D asset per scene, this is a serious blueprint to look at, provided you treat the small-absolute empirical setting as a demonstration you want to reproduce at scale before you rely on the efficiency gap.
