Duopra, by Chiyu Chen, Pengzhou Cheng, and Yuezhao Ma, at Shanghai Jiao Tong University with Tencent, is a full-duplex agent that can talk and act at the same time. The phrase full-duplex comes from telephony, where a phone lets both parties speak simultaneously, and in the world of spoken language models it means the system can listen, talk, and run tools without taking turns. That sounds like a small extension of what a voice assistant already does, but the authors argue it is a different problem, and that most of the failures in existing full-duplex systems do not come from the talking or the tool-calling themselves, but from the seam between the two.

That seam is where the real contribution lives. The standard split for a spoken agent has a frontend that manages the conversation, decides when the user has finished a request, and hands a complete instruction to a backend that executes it. The problem is that the handoff is fragile. If the frontend starts the backend before the user has finished speaking, it fires on a partial request. If it waits too long, the user has already moved on. The authors show, using a benchmark called Full-Duplex-Bench version 3, that for a strong real-time audio model paired with a tool harness, most of the failures in the streaming pipeline happen before any domain tool ever executes. The model is not failing at the task; it is failing at deciding when the task is complete enough to start.

<!--C1-->

The fix is to collapse the fragile handoff into a single, self-contained action interface. In Duopra, the backend is treated as just another tool, and the model, rather than deciding separately when to start and then what to do, produces a single natural-language request that is complete enough to execute on its own. The same interface is used whether the model is calling a tool directly or delegating to the backend, so there is no separate decision about when a request is finished. The authors call this the move from full-duplex conversation to full-duplex agency, because the system can now act mid-conversation on a request it has fully specified, without a brittle seam between the two. The training is done in three stages: first, a supervised fine-tuning phase on protocol data that teaches the model the action interface; second, a full-duplex reinforcement learning phase that rewards timely and complete execution, not just correct execution; and third, a repair stage that re-conditions the talker on the updated model after the thinker has been updated, which is a small but important detail because the speaking component and the reasoning component drift apart if you are not careful.

The numbers are where the approach earns its keep. On the benchmark, with the same backend, the pass-at-one rate, which is the chance the model completes the task in a single attempt, rises from 4.7 percent for the base real-time audio model to 44.7 percent under Duopra, which is almost a ten-fold improvement and the single most striking number in the paper. The model also reaches 47.7 percent when calling tools directly and 49.3 percent when delegating to a DeepSeek backend, and it improves the takeover rates, the fraction of times the user has to interrupt the model, on the earlier version of the benchmark. The authors are careful to attribute the gain to the initiation and execution discipline rather than to a better tool, because the backend is held fixed. The skeptical read has to note where the win is narrow. The benchmark measures whether the model produces a request complete enough to execute, and the huge jump from 4.7 to 44.7 percent is partly a statement about how badly the baseline was broken, not only how good Duopra is. A 4.7 percent baseline is so low that almost any reasonable fix produces a large relative gain, so the absolute 44.7 percent is the number to weigh, and it is still far from a rate that would make a voice agent dependable for real multi-step work. The reinforcement learning phase, which rewards timeliness and completeness, is doing a lot of the heavy lifting, and the paper does not fully isolate how much of the gain comes from the interface change versus the RL objective. That matters, because if most of the win is the RL objective, then the interface is less of a structural insight than it appears. The third training stage, the talker re-conditioning, is the kind of detail that is easy to understate in a writeup and hard to get right in practice, and the fact that it is included at all is a sign the authors have actually run this pipeline rather than just reasoning about it.

The deeper point, though, is that the paper reframes the problem in a way that is independently useful. By showing that most of the failures happen before the tool ever runs, the authors argue that the bottleneck in full-duplex agents is not the perception or the execution but the initiation, the decision of when a request is ready. That is a claim you could test on other systems, and if it holds, it redirects a lot of effort away from better speech recognition and better tool use and toward better request specification. That is a genuinely different framing, and it is the part of the paper I would take with me even if the specific numbers did not hold up under independent replication. It is worth stressing how unusual the control is for this area. Most full-duplex papers measure the conversation experience, and a few measure tool success, but almost none isolate the request-completeness variable the way Duopra does, holding the backend fixed and only changing how the model produces the request. That isolation is what lets the 4.7 to 44.7 percent jump be attributed to the interface rather than to a better model or a better tool, and it is the methodological strength the paper does not get enough credit for. The discipline also generalizes beyond the specific tools in the paper, because the rule is about the shape of the request, not the identity of the backend, which means any agent that calls external tools, from a web agent to a code runner, could in principle adopt the same request discipline. That is the long-term value of the work, and it is larger than the single benchmark it reports. The three-stage training recipe is also worth a moment, because it is the part most likely to be copied. The first stage teaches the model the basic discipline of forming a request, the second applies the reinforcement learning that rewards timeliness and completeness, and the third re-conditions the talker so the spoken response is tied to the action the model is about to take. That third step is what keeps the voice and the tool call in sync, and it is the kind of detail that separates a paper from a working system. A reader who only looks at the headline pass-at-one number would miss that the result depends on all three stages working together, and that the interface change alone, without the RL objective, would not reach the same level. On balance, Duopra is a focused, well-controlled systems paper that makes a large, well-measured improvement on a narrow but important bottleneck, and the honest summary is that it proves the bottleneck is real and addressable, while leaving open how far the same discipline carries into longer, multi-turn agency. For a field that has spent the last year arguing about whether voice agents are ready, this paper is a useful and concrete data point that the readiness gap may be less a model-capability problem than a specification problem, and that is a diagnosis a lot of teams can actually act on.
