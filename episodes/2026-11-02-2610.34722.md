CEPO: A General Framework for Improving Prompt Optimization in Multi-Agent Systems, by Jongha Kim, Seohyun Lee, and Jonathan Minho Chung, from Korea University, KAIST, and Google Cloud AI Research, is a framework for optimizing the prompts of a multi-agent system rather than one agent at a time. The core claim is that a multi-agent system has two distinct prompt jobs, system-level coordination, which agent talks to which agent and in what order, and agent-level execution, what each individual agent actually does, and existing prompt optimizers blur those two together inside each agent's prompt. CEPO splits them: a single shared coordinator prompt that is refined consistently across the whole system, plus separate agent-specific executor prompts, and it guides the updates of each according to its role. CEPO itself does not do the search, it supplies the prompt structure and the optimization guidance, and any off-the-shelf prompt optimizer does the actual optimization.

That framing is the whole contribution, and it is a clean one. The motivation is that in a document-understanding system, for example, the agents gather multimodal evidence, a critic reviews a draft answer, and a reflector revises it, and the quality of the final answer depends on both the coordination, does the critic actually get the right evidence, does the reflector fire when it should, and the execution, does each agent do its local job well. If you optimize each agent's prompt in isolation, you are optimizing the execution half while the coordination half stays fixed and unexamined, and the two interact in ways a per-agent optimizer cannot see. The failure mode is concrete: a per-agent optimizer can make the reflector write better revisions, but it cannot tell the reflector when to fire, because that is a coordination decision that lives outside any single agent's prompt. CEPO's coordinator prompt is where the interaction lives, and it is the piece that per-agent optimization leaves untouched. The reason the split helps is that the two roles have different failure signatures and different update cadences: the coordinator prompt is stable, it encodes the system's workflow and rarely needs to change, while the executor prompts are task-specific and churn more, so optimizing them on the same schedule and in the same prompt space is a mismatch.

The method is deliberately optimizer-agnostic, and that is both its strength and its limit. The paper applies CEPO to four existing prompt optimizers, PE2, OPRO, ProTeGi, and MASPO, and reports that the structure improves all four. The experimental surface is eleven benchmarks across four domains, document understanding, mathematical reasoning, code generation, and video understanding, which is a broad claim to support and the breadth is doing real work for the general-framework label. The coordinator prompt is optimized as one shared object across all the agents, so the same coordination rules are refined consistently, and each executor prompt is optimized for its own role, with the update guidance telling each optimizer what its prompt is actually responsible for. The initialization is a detail worth noting: the coordinator prompt is seeded by querying GPT 5 mini with a brief description of the agent composition, so the starting point is a plausible workflow rather than an empty template, and the executor prompts start from the defaults published with each system. In the controlled document-understanding study, the agent backbone is Qwen 3.5 at 4 billion parameters, served locally on 8 H200 GPUs, with a separate DocAgent variant using GPT 5 mini through the API, and the video experiments use Qwen 2.5 at 7 billion as the master agent with grounding and vision agents on GPT 5 mini.

The update guidance is where the framework is concrete. The coordinator prompt is told to encode only system-level rules, which agent produces what, in what order, and when a role should fire or defer, and it is optimized as one shared object so that every agent in the system is refined against the same coordination rules at once. The executor prompts are told to encode only the local task, how this agent does its own job given whatever the coordinator hands it, and each is optimized independently against its own role. The separation is enforced in the optimization loop, not just in the prompt layout, so the optimizer for the coordinator never edits an executor's instructions and vice versa, which is the difference between a prompt structure and a framework. That is also why the framework can wrap any optimizer, PE2, OPRO, ProTeGi, and MASPO each bring their own search heuristic, reflection mechanism, or proposal method, but they all operate on the same split prompt structure with the same role-based guidance.

The detail that matters for whether this is a real effect or a budget effect is the optimization-budget analysis. They vary the optimizer budget, the number of optimizer API calls, and they show that CEPO's gains do not come from spending more compute. With PE2's default budget of three coordinator iterations and three executor iterations, which matches the empirical plateau, pushing the budget to four and four yields no improvement, and at a minimal budget of one and one, CEPO still shows a substantial benefit with far fewer API calls. So the gain is from the structure, separating coordination from execution, not from an inflated budget. They also find that a sequential optimization schedule, letting each role converge before switching, outperforms an alternating one, because alternating introduces instability, and that optimizing the coordinator executor yields the highest accuracy at 61.0, beating the next-best target at 59.1. The agent-count study shows the margin over the unoptimized baseline grows from 3.9 at two agents to 6.9 at five agents, which is the scaling-with-agents claim, and vanilla PE2 is less stable, even falling slightly below baseline at three agents on one configuration. The per-configuration breakdown, reported in the supplement, is the version of that result to actually read, because the headline is an arithmetic mean over configurations that produce a valid final answer, and the within-group spread is where the instability shows up, with the GENERAL, TEXT, and SUM configuration collapsing under vanilla PE2 at three agents. The optimization-target ablation is a smaller but cleaner result, optimizing the coordinator executor yields the highest accuracy at 61.0, beating the next-best target, the TEXT executor, at 59.1, and the gap tells you that in a document QA system the execution half is where the prompt effort buys the most, which is the kind of per-system detail a practitioner would want before deciding where to spend prompt-optimization budget.

The things I would want to check before adopting this. First, the optimizer-agnostic design means the results are an average over four different search procedures with different inductive biases, so the per-optimizer breakdown matters and a consistent improvement across all four is more credible than a single-optimizer win, but it also means CEPO is not a method you can point to a single training recipe for, it is a wrapper whose value depends on the optimizer underneath. Second, the four-domain breadth is mostly demonstrated, not deeply analyzed, and the controlled budget and scaling studies are all on the one document-understanding system, so the cross-domain generalization of the budget-efficiency and agent-count results is inferred rather than shown. Third, the absolute accuracy numbers are modest, a 61.0 on the document QA task, and the paper is honest that the gains are a few points, which is exactly the right size for a structural improvement but not a breakthrough.

My verdict is that CEPO is a sensible and well-controlled structural contribution, separate the shared coordination prompt from the per-agent execution prompts and optimize each by its role, and the budget analysis credibly shows the gain is structural rather than compute-driven. But it is an incremental, wrapper-level result, a few points of accuracy on a handful of systems, and the cross-domain generalization is demonstrated but not deeply stress-tested, so it is a reasonable thing to try on top of an existing prompt optimizer, not a reason to rethink how you build multi-agent systems.
