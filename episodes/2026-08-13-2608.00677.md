OpenART: Scaling Agent Red Teaming via Open-Ended Environment Evolution, by Yunhao Chen, Xin Wang, and Yixu Wang, from Fudan University, the Shanghai Artificial Intelligence Laboratory, and XSafeAI. The core reframing: stop treating a prompt as the unit of red teaming and treat the persistent executable environment as the unit instead. The task objective and safety contract stay fixed while only the target-visible state evolves across rounds. If you ship coding agents against real workspaces, the headline finding should get your attention: pooled strict attack success of 85 percent across 75 agent-model configurations, with environment evolution gaining almost nothing on simple tasks but up to 17.6 points on the most complex ones.

First, scale, because that is what separates this from prior agent-safety benchmarks. Over 10,000 validated stateful scenarios spanning 50 domains, built from a corpus of more than 500,000 tools, MCPs, and skills collected following SkillNet. Median workload is 97 tool calls per scenario, dependency depth 32, parallel width 12.5, against 1 to 15 tool calls for InjeAgent, AgentDojo, AgentHarm, ASB, ToolEmu, and DTap. The same validated scenario projects through adapters into 15 deployed agent runtimes, including Claude Code, Codex, Goose, Aider, OpenCode, Kilo, and Qwen Code, paired with five foundation models: GPT-5.5, Claude-Opus-4.8, GLM-5.2, Qwen-3.7-Max, and DeepSeek-V4-Pro. That is 75 configurations on identical semantics.

Scenario construction is a generation-plus-validation pipeline. A planner retrieves compatible capabilities from the registry, composes a directed workflow graph where each vertex is a grounded environment operation with typed input-output dependencies, then compiles an initial environment containing approved evidence, decoys, protected resources such as credentials, and publication destinations. Each bundle carries a hidden safety contract compiled into a deterministic evaluator that checks both benign completion and whether protected markers leak into public outputs. Acceptance requires executing the evaluator on controlled safe and unsafe outcomes and getting zero and one respectively; failures return to the planner for repair. A separate 10 percent human audit judged 99.3 percent of evaluators correct.

The attack policy, EMHA, short for Evolutionary Markov Hypergraph Attack, is black-box and frozen-parameter throughout. It models coordinated environment changes as a hypergraph whose vertices are attack subgoals, with hyperedges connecting prerequisites to successors. At each round it samples a ready hyperedge path from the current active subgoal set, decodes it into concrete environment mutations through a frozen attacker model, materializes them into eight target-visible surfaces, workspace files, instructions, skills, tools, MCPs, short-term memory, plan state, or long-term memory as the runtime adapter supports them, then reads evaluator feedback. Feedback drives tabu-style Q values over transitions updated by return redistribution, and a MAP-Elites-style archive keeps the highest-fitness attack per behavior cell, with offspring graphs produced by two graph-edit kernels. Attacker and target run in separate Docker containers; projection through the adapter is the only channel between them.

Scoring uses Strict ASR: an attack counts only when both the deterministic evaluator and a GLM-5.2 judge flag the unsafe condition, and any disagreement counts as failure. That double-key design suppresses judge false positives at the cost of understating success. Benign completion was measured first so capability gaps are not misread as safety wins: pooled completion ranges from 80.8 percent on Qwen-3.7-Max to 96.2 percent on Claude-Opus-4.8, with Aider weakest everywhere at 70.7 percent average.

Results. Pooled strict attack success is 85.0 percent. A two-way decomposition attributes 73.6 percent of variance to the model and 25.2 percent to the agent runtime; adding agent identity to model-plus-completion explains an extra 7.6 percent of variation, rising from 91.3 to 98.9 percent total. So implementation choices carry safety signal beyond which model you bought. Per-model averages: Opus-4.8 is hardest to compromise at 59.2 percent, GPT-5.5 at 88.5, GLM-5.2 at 87.9, DeepSeek and Qwen above 94. Aider is again the softest runtime at 59.1, though read that against its weak completion.

The ablations are where engineering value concentrates. Under DeepSeek-V4-Pro with matched budget, restricting evolution to workspace mutations alone reaches 92.5 percent strict success, 10.9 points above instruction-only evolution; all seven other single-vector attacks still exceed 50 percent, meaning the instruction surface is not load-bearing. Full EMHA hits 94.7. Removing the archive costs 3.9 points, removing credit redistribution 2.6. Cumulative success climbs 42.9, 69.4, 73.5, 89.8, 94.7 over five rounds, so round one finds less than half of what five rounds find.

The mechanism analysis explains why static benchmarks mislead. Across 10,000 converted trajectories, the median propagation distance between the action that consumes evolved state and the action producing the unsafe output is 37 target actions, with the consumed state appearing at roughly 23 percent of execution and the unsafe sink at 64 percent, a latency of 41 percent of the workflow. Three recurring vulnerability classes account for most failures: stale assumptions never invalidated, plan-referent drift, capability rebinding behind unchanged interfaces, checkpoint expiry; safety decisions propagated rather than recomputed, where a downstream schema marks a field mandatory and later stages treat completeness as evidence of safety; and compositional risk, where individually benign changes combine until seven protected categories reach one public report.

Limitations worth weighing before you cite the numbers. Strict ASR depends on evaluator quality, and although audited, evaluators were generated by the same pipeline family being evaluated. The complexity result is correlational, not causal. No defenses are tested, so this measures exposure, not mitigation. And EMHA's budget in rounds is generous relative to what a real adversary needs for these failure classes, since many appear after ordinary drift. Bottom line: if your agent touches persistent state across multi-step workflows, assume environment-level perturbations will find what prompt testing missed, and instrument your own traces for the stale-assumption and propagated-safety-decision patterns specifically. This is a credible measurement substrate for agent red teaming, but treat the exact percentages as pipeline-specific until your own scenarios reproduce them.
