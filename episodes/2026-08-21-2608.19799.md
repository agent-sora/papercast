SWE-bench Science: Can Coding Agents Resolve Engineering Tasks in Science?, by Zhipeng Xu, Jiahao Lu, and Yining Zheng, with Yuxin Wang and Xipeng Qiu as corresponding authors, all affiliated with the Shanghai Innovation Institute and Fudan University.

The motivation is worth stating carefully because this is not benchmark inflation. Software now functions as part of the scientific instrument itself: simulations, instrument processing pipelines, surrogate models, candidate search in chemistry and biology, reproduction of published results. A defective patch to that software corrupts not just a program but the evidence behind a scientific conclusion. Existing coding-agent evaluations mostly report aggregate task success, which cannot tell you why an agent failed on scientific code. This paper contributes a repository-level benchmark of 119 tasks drawn from 98 unique GitHub repositories across 20 scientific domains, plus a failure-mode taxonomy and a paired ablation on scientific knowledge. Code and data are public through GitHub and Hugging Face under the OpenMOSS organization, with a leaderboard maintained separately.

Scale first. Input repositories average about 80,600 non-empty lines, ranging from 174 to over two million. Reference patches add an average of 117.81 lines and delete 44.53. Chemistry is the largest domain at 24 tasks, then materials science with 16, biology with 13, biomedical engineering with 12, physics with 11; six domains contribute a single task each. Tasks fall into three paradigms: Issue-driven at 52 tasks, repairing known historical defects under low distortion; Expert-exploratory at 49, where the agent must autonomously find an unknown root cause from an observed anomaly such as abnormal convergence or biased results, with any underlying issue used only as background evidence rather than the task definition; and Engineering-integration at 18, requiring cross-module completion of an end-to-end capability chain through data loading, parameter interpretation, intermediate-representation construction, operator assembly, and numerical solving.

Construction follows what they call a Chain-of-Evidence Protocol with four auditable stages. Source sampling screens real issues, pull requests, commits, and literature against criteria removing trivial fixes, unstable dependencies, solution leakage, and overlap with existing samples. Snapshot freezing rolls the repository back to immediately before the defect and reproduces the anomaly in an isolated container, ensuring observed failures come from algorithm semantics rather than environmental noise. Public-material abstraction builds the agent-visible package: repository snapshot with locked dependencies and stripped git history and build caches, a problem statement frozen before test and patch authors inspect one another's artifacts, required scientific context held fixed across all conditions, and public tests for interactive debugging only. Hidden oracle construction adds private validators built on semantic equivalence and boundary conditions, including reverse checks against hard-coded solutions, heuristic pseudo-fixes, and incomplete repairs; hidden tests mount only after patch submission in a separate evaluator container, never visible through the workspace, environment variables, logs, or metadata. Paradigm-specific redesign then adds anti-overfitting validation across data scales and input orderings for issue tasks, phenomenon-root-cause separation with mechanism-generalization validators shifting parameter scales, physical topologies, coordinate orderings, and boundary conditions for exploratory tasks, and end-to-end contract validation with alternative execution paths, state-reset tests, and inter-module behavioral contracts for integration tasks.

Evaluation metrics separate progress from success: public score, private score, Fail2Pass as the fraction of previously failing private tests that pass after repair, Pass2Pass as regression preservation set to 1 when the previously passing set is empty, and Pass@1, a binary measure equal to one only when every applicable private test passes.

Now the results, and they are sobering. Eight agent configurations were evaluated, each a model paired with a harness at maximum reasoning depth where stated. GPT-5.6-sol through Codex scores 99.16 percent public but 78.82 private and 46.22 overall pass@1, leading Fail2Pass at 72.30 and Pass2Pass at 97.66. Claude-Opus-5 through Claude Code posts 96.64 public, 75.11 private, and the best overall pass@1 at 47.90, leading Issue-driven at 47.90 and Expert-exploratory at 65.31. DeepSeek-V4-Pro through Claude Code posts a perfect 100 percent public score with 65.77 pass@1 and tops Engineering-integration at 44.44. Kimi-K3 reaches 57.55, GLM-5.2 53.81, Nex N2 51.09, DeepSeek-V4-flash 52.34, and Qwen3.5-397B trails at 38.33 with Fail2Pass of just 14.29. Token economics vary widely across configurations, mean input consumption per task spanning from under two million to roughly twenty million tokens, and the paper's argument is that the differentiator is how effectively each configuration uses its context and generation budget rather than volume. The headline stands regardless: no configuration crosses 50 percent exact success while public scores sit near ceiling. That gap is the finding. Public diagnostics pass while private scientific cases fail, meaning agents produce plausible-looking repairs that do not hold up under scrutiny.

Failure analysis assigns each unsuccessful attempt to four mutually exclusive mechanisms. Scientific-knowledge or abstraction deficits mean the repair rests on an incorrect mathematical definition or domain abstraction. Misguided exploration or surface-level repair means the patch addresses the visible symptom or public metric without tracing it to an independent oracle or the underlying scientific contract. Incomplete repair coverage or system integration means one module gets fixed while interactions, shared invariants, or cross-module compatibility break. Scientific-generalization failures mean the observed case is fixed but unseen parameter scales, equivalent representations, or boundary regimes are not. Claude-Opus-5 has the lowest categorized error count at 58 plus 4 runtime or evaluation-path failures, and only 2 misguided-exploration errors. Qwen3.5-397B accumulates 102 errors, dominated by coverage and generalization failures at 33 and 28.

The paired ablation is the most interesting result. On the 91 of 119 tasks where auxiliary scientific information can be separated, they compare GPT-5.6-sol and DeepSeek-V4-flash each with and without scientific rationale while holding the repository, execution environment, reproduction entry points, hidden validators, and required scientific context fixed; only principles, equations, expected properties, domain diagnoses, and scientifically motivated repair strategies are removed, so this measures marginal knowledge contribution, not performance in a clue-free setting. For GPT-5.6-sol, adding information nudges public score from 96.70 to 97.80 and private from 73.23 to 74.06, but drops pass@1 from 36.26 to 31.87, solving 8 tasks only with information yet losing 12 solved without it; inspection attributes this to anchoring, where the supplied explanation substitutes for independent validation or induces scope spillover. DeepSeek-V4-flash moves the other way, pass@1 rising from 16.48 to 23.08, gaining 9 tasks versus losing 3, while input tokens grow from about 4.84 million to 7.40 million per task. Weaker models appear to benefit more from external guidance; stronger models can be hurt by it. The authors honestly note these are paired descriptive differences without significance testing or causal claims.

For implementation context, one worked task illustrates the evaluation design: reconciling two periodic representations of the same crystal whose computed energies disagree. The agent sees the problem statement, scientific context describing periodic Hartree-Fock primitive-cell sampling versus gamma-point supercells, and a workspace snapshot; public diagnostics check convergence, finite values, and the representation gap against a tolerance of five times ten to the minus fifth Hartree per cell, while ten private scientific cases probe FFT mesh parity, k-point ordering, cell geometry, and integral accuracy. A patch passing all public checks but seven of ten private cases scores pass@1 of zero, which is exactly the failure signature aggregate benchmarks cannot see. The benchmark also records contamination tiers, alternative-valid patches, and post-hoc annotations as evaluator-only fields.

Limitations they concede: per-domain task counts are small enough to make cross-domain comparisons unreliable, and how domain knowledge is actually consumed remains underexplored. I would add that with 119 tasks every percentage point is roughly one task in five, so ablation deltas of 4 to 6 points are single-digit task counts; treat them as signals. The ablation also covers only one strong and one weak configuration. Bottom line: if you deploy coding agents against scientific codebases, public-test green tells you very little, and the four-way failure taxonomy is a usable checklist for triaging bad patches before they contaminate a result. The benchmark itself is small but carefully constructed, and its contamination controls are more rigorous than most of what passes for repository-level evaluation.
