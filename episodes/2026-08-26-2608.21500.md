SecOPD: Mitigating Adaptive Prompt Injections by On-Policy Distillation, by Yibo Peng, Long Lian, David Wagner, and Sizhe Chen at the University of California, Berkeley, with Wagner and Chen jointly supervising. The paper attacks a specific and widely repeated failure: model-level prompt-injection defenses trained with sequence-level feedback look strong on paper and then collapse under an adaptive attack that optimizes against them. The proposed fix changes only the training signal — per-token scores derived from the same model shown a clean version of each input — and with that single change, attack success rate against the strongest adaptive attack drops from ninety-four percent to nine.

Start with the threat model, because the paper's scope is narrower than headlines suggest. A trusted user instruction sits in one message; untrusted external data — web pages, documents, tool outputs — sits in another, using a dedicated input message type added to the chat template. The adversary controls only the untrusted field and may embed any instruction there. The defended model should keep using external data as context while never obeying instructions inside it. This is indirect injection where the user is benign; the authors state plainly that jailbreaks, direct injections, and malicious-user attacks are out of scope. They also assume the system already knows which input parts are trusted, which sidesteps a hard open problem rather than solving it. Training pairs every clean example with an attacked twin differing only in whether an injection sits inside the untrusted field — most injections placed at its beginning or end, occasionally in completion style behind delimiters — so the two contexts remain otherwise identical. Typical injected goals ask the model to echo a fixed marker sentence or swap its answer for some unrelated instruction.

The diagnosis of prior work is the paper's intellectual core. Sequence-level defenses like Meta-SecAlign build preference pairs — secure response versus injected response — and train with DPO; other recipes assign one scalar reward per rollout via GRPO and a judge. Both assign their label to the response as a whole, which breaks precisely on the case that matters most: hybrid responses that answer the benign task and partially comply with the injection. Such a response is neither fully preferred nor fully rejected, so the training signal cannot say which tokens were the problem. Prompt-injection security is arguably a token-span property — obey this instruction from context, ignore that one — and sequence-level feedback simply cannot express it.

SecOPD borrows on-policy distillation from utility training and repurposes it for security. The mechanics are clean. For each clean training example of instruction plus data, synthesize an attacked twin by inserting an injection drawn from a pool, mostly at the beginning or end of the untrusted block, occasionally as delimiter-completion style attacks. The student samples a rollout from the attacked input. The teacher — the frozen initialization model, before any defense training — scores every sampled token, including reasoning tokens, but conditioned on the clean input where the injection never existed. The token-level advantage is the difference between those two log probabilities, used as a fixed signal with gradients flowing through the student likelihood only. The interpretation is exact: if the clean-context teacher finds your next token plausible but the attacked-context student loves it, that token probably serves the injection, and it gets suppressed; tokens serving the genuine task get high teacher probability and are reinforced. One rollout thus carries different feedback for different spans, which is what DPO and GRPO structurally cannot do. No security judge, no reward model — the supervision is entirely "behave as you would have without the attack."

Training details matter for replication: nineteen thousand examples built from Cleaned Alpaca following the Meta-SecAlign protocol, Tinker as the training framework, LoRA-style adapter-only updates on Qwen3.6-27B with student and teacher sharing initialization. Evaluation is where the Berkeley group does unusual due diligence. Against static injections they report SEP results, but static robustness is exposed as mostly meaningless — Meta-SecAlign cuts static attack success from ninety-nine point four to twenty-eight point nine percent, then loses almost everything under PISmith, a purpose-trained RL adversary tuned against each target model: ninety-four percent of intrusion attempts still succeed, barely better than the undefended model's ninety-seven point nine. GRPO-based defense gets PISmith down to sixty-one point two. SecOPD takes it to nine percent — pass-at-ten measurement over one thousand twenty-four test examples, with an audited judgment protocol: substring matching demoted to candidate filtering, then two language-model judges queried three times each, success counted only on six yeses. On AgentDojo tool-calling pairs, nine hundred forty-nine of them, SecOPD reaches four point seven percent attack success versus five point five for Meta-SecAlign — modestly better, and notable mainly because agentic tasks never appeared in training; GRPO posts zero point seven there but at a steep utility price.

The deployment story is part of the contribution. Training runs through the Tinker framework with adapter-only updates, so the compute footprint stays modest for a defensive recipe aimed at this model class. The judging protocol deserves equal attention because attack-success numbers are notoriously gameable: substring matching is defeated by light paraphrase, so the authors demote it to nominating candidates for review, then require six agreeing language-model calls before any attempt counts. The underlying benchmark contributes roughly nine thousand instruction-following samples, while AgentDojo supplies nine hundred forty-nine tool-calling pairings drawn from realistic application suites. One limitation the authors volunteer cuts against detectability: defended models reason without any hesitation markers about injections, because training teaches them to behave as if untrusted instructions did not exist rather than to notice and refuse them — so downstream defenses that watch reasoning traces lose their signal.

Utility is the usual casualty of defensive tuning, and here the comparison gets honest. Across seven benchmarks, GRPO's average drops to eighty-three point one with visible damage on instruction following, tool tasks, and competition math. Meta-SecAlign preserves everything — eighty-eight point five average — and keeps essentially none of its security under adaptation. SecOPD holds eighty-eight point one average, matching the undefended model: eighty point one on AlpacaEval2, eighty-eight point six SEP utility, eighty-four point one unchanged on MMLU-Pro, GPQA-Diamond actually up at eighty-one point three. GSM8K moved a third of a point downward while GPQA-Diamond and Minerva-Math ticked upward — plausibly noise, certainly no systematic capability tax. A third caveat follows from the recipe itself: because only student adapter parameters are updated, the defense lives in a detachable layer, which simplifies rollback but means any full-parameter variant needs its own validation. The failure audit of residual regressions builds trust: of forty-six Minerva-Math problems lost, only four involved genuinely wrong mathematics; twenty were corrupted or unrelated answers, twelve formatting losses, ten early terminations after closing the reasoning marker.

Case studies show the mechanism visibly: given a biodiversity question whose untrusted text ends with an appended-seasons injection, both baselines answer correctly and then append the injected sentence anyway; the SecOPD-trained model answers and stops. The case study uses thinking disabled, matching how the judges scored the benchmarks, and the authors present it as illustration rather than evidence — the quantitative tables carry that burden.

A skeptical read still has material. The nine percent number is against one adversarial family — formidable, adaptive, but named and bounded, and the authors concede future adversaries will improve; treat nine percent as a measurement against today's best published technique, not a ceiling or floor. The chat template bakes trust boundaries into message structure at fine-tuning time, so integrating this with an arbitrary existing agent stack means retraining with your real boundary convention. Nothing here addresses multi-step scenarios where useful instructions legitimately arrive through untrusted channels. And distilling from the undefended model on clean inputs assumes clean behavior was worth keeping. Bottom line: this is the most convincing model-level prompt-injection result published to date — an order-of-magnitude gain against a genuinely adaptive adversary with no utility bill, achieved by fixing credit assignment rather than adding machinery — and it should reset expectations for every defense evaluated only against static attack libraries.
