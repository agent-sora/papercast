The paper is AgenticRoboRL, from Xinxin Liu at the University of Central Florida, Bingxin Xu at the University of Southern California, and Wenrui Bao, with the rest of the group at Michigan State University. The setting is agentic robotics, where a planner model, typically a large language model, drives a robot by invoking learned VLA skills or writing control code over perception and control APIs, observing the execution, and deciding the next move over many rounds. The field's recent gains, the authors note, have come from better harnesses and external memory, with closed-source frontier models serving as the planners, but those approaches leave the planner itself untouched. Their question is the one that worked for coding agents: does post-training the model itself, supervised fine-tuning plus reinforcement learning, also improve the robot planner?

The complication that makes this non-obvious is that robot harnesses execute a planner's response in different ways. In one harness the planner calls a VLA skill and a learned policy executes it. In another the planner writes control code and a motion controller runs it. The feedback returned to the planner and the definition of task success differ between harnesses too. So a training pipeline has to support both execution mechanisms without changing their interfaces. AgenticRoboRL solves this with harness-specific adapters that connect recorded planner interactions with task outcomes, so a single RL pipeline can train on both skill invocation and code generation while the execution components stay fixed. The recipe is two stages. First, supervised fine-tuning on successful demonstrations gives the planner a working starting point. Then multi-turn reinforcement learning on recorded planner requests and responses, where the adapters associate each interaction with the episode outcome, and only the planner is ever optimized.

The results on LIBERO-PRO, a hard manipulation benchmark, are the headline. A nine-billion-parameter planner starts at eighteen point one percent success without external memory. After SFT it jumps to sixty-five point one percent, and after the multi-turn RL it reaches seventy-one point zero percent, still with no external memory. For context, Codex with GPT-5.5 plus external memory gets seventy-two point one percent on the same benchmark, so a nine-billion open planner, post-trained and memoryless, lands within a point of a frontier closed system with memory. The same checkpoint transfers to LIBERO-Plus without any additional training, reaching seventy-two point two percent where the original model sat at nineteen point two percent. On the code-generation harness, CaP-X, post-training lifts success from two point seven percent to twenty-eight point five percent, a smaller absolute number but a ten-fold relative improvement from a near-zero base. They report a twenty-seven-billion planner variant too, which with memory reaches seventy-four point zero percent, and they commit to releasing the framework and the trained checkpoints.

The training details are what separate a framework paper from a recipe, and this one supplies them. The supervised fine-tuning stage runs on the recorded planner interactions, where the harness adapters convert each episode into five standardized fields: the model input, the generated response, the task context, the execution outcome, and a success label. The adapters are the whole integration surface, and they are what make the method portable across harnesses without touching the planner. For the skill-invocation harness, an episode is the planner's sequence of skill calls plus the outcome; for the control-code harness, it is the generated code plus the execution result. The RL stage runs on top of the best supervised checkpoint, selected by validation among ten checkpoints, and the main result uses the checkpoint at training step five hundred sixty-three. The RL is group-based: each round covers sixty-four groups, where a group is one task with one initial state, and each group is attempted six times, for three hundred eighty-four episodes per round; they run nine rounds and report the checkpoint after round six. Within an episode, at most sixteen responses are selected for the policy update, and the objective carries no KL or entropy term, which is a deliberately simple setup, closer to outcome-weighted selection than to a carefully regularized policy gradient. That matters for interpretation: the gains come from the quality of the success signal and the task coverage, not from elaborate reward shaping, which is both a strength, the signal is the ground truth of execution, and a limitation, the method needs an executable harness with clean success labels, which is exactly the part that does not transfer to settings where you cannot run the robot or the simulation.

The benchmark choice deserves its own paragraph, because it is what makes the headline number mean something. LIBERO-PRO is explicitly a robustness and anti-memorization benchmark: it perturbs object positions, appearances, and scene layouts beyond what the standard LIBERO splits contain, so a planner that has memorized the canonical task layouts fails, and a planner that has actually learned to plan under perturbation survives. That is the right test for a post-trained planner, because the failure mode you are trying to fix, the planner that worked in the training suite but collapses in deployment, is a generalization failure, and a memorization-friendly benchmark would hide it. The fact that the same checkpoint then moves from nineteen point two to seventy-two point two on LIBERO-Plus, a different robustness suite, without any additional training, is the transfer evidence, and it is stronger than the headline comparison, because it shows the learned planning behavior is not specific to one benchmark's perturbation distribution. The CaP-X numbers, the two point seven to twenty-eight point five on the code-generation harness, should be read as the weaker leg of the cross-harness claim. The relative improvement is large, ten-fold, but the absolute level is still low, which means the control-code path, where the planner has to emit executable motion code rather than invoke a pre-trained skill, is still a harder task and the current post-training mostly fixes the skill-invocation side. The paper's honest framing is that the framework supports both, and the evidence that both improve, rather than that both reach high absolute performance.

The skeptical part. The comparison that sells the paper, a nine-billion model within a point of GPT-5.5-plus-memory, is the kind of single-benchmark, single-configuration result that needs a lot of salt. LIBERO-PRO is one benchmark in one simulation suite; the memory asymmetry is real, the frontier system gets external memory and the post-trained planner does not, and the honest reading is that post-training closed most of the gap that memory alone would close, not that the small model matched the frontier model. The SFT-to-RL decomposition, sixty-five then seventy-one, tells you most of the gain comes from imitation of successful demonstrations and that the RL adds a smaller but meaningful tail, which is a healthy result but also means the method is only as good as the demonstration coverage for the task distribution. The cross-harness claim, one pipeline for both skill invocation and code generation, is the more generalizable contribution, but the CaP-X numbers are low enough that the code-generation side of the story is still early. And the external memory ablation cuts both ways: the twenty-seven-billion model with memory scores higher than without, which is expected, but it means the memoryless result for the nine-billion model should not be read as a dismissal of memory, only as evidence the two levers are complementary.

The verdict: this is a credible first demonstration that coding-agent post-training transfers to robot planners, and the harness-adapter design that unifies skill invocation and control-code generation under one RL pipeline is the durable piece. If you run agentic robotics systems, the result to take away is that a small open planner, SFT-then-RL-trained on successful rollouts, gets most of the way to frontier-plus-memory performance on hard manipulation, which changes the economics of who gets to be the planner; if you are evaluating the claim, the single-benchmark frontier comparison is the first thing to challenge.
