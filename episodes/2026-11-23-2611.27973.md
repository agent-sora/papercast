Title: MemOnce: A Scalable Memory Architecture for Large Language Models
Authors: Chang Nie, Chaoyou Fu, Songlin Liu
Labs: Nanjing University, University of Science and Technology of China
Arxiv: 2611.27973
Day: 2026-11-23
Upvotes: 10
Link: https://arxiv.org/abs/2611.27973
---

MemOnce, by Chang Nie, Chaoyou Fu, and Songlin Liu, at Nanjing University and the University of Science and Technology of China, is an architecture for giving a language model a memory that does not grow with the conversation. The problem it targets is one that has become unavoidable as models move from single prompts into long, continual sessions with agents and users. A standard transformer keeps a key-value cache for every token it has seen, in every layer. That cache grows linearly with the context length, and the computation to use it grows quadratically, so a million-token session is a genuinely expensive one. The paper frames the design goal precisely: a memory that lets the model recall fine-grained details, runs in linear time, and keeps its GPU memory footprint bounded no matter how long the conversation gets.

The architecture rests on two coupled ideas, both aimed at the same bottleneck. The first is a memory encoder-decoder. Instead of caching every token at every layer, the model keeps only a small trailing subset of the final layer's hidden states as a compact, persistent memory bank, and then decodes those states back into key-value caches for the attention layers on demand, using lightweight, layer-specific projection networks. The second is what the authors call memory sparse attention. For each new input, the model computes a set of retrieval indices once, picks the handful of memory states that look relevant to the current task, and reuses those same indices across every layer and every decoding step rather than recomputing them. The combination is meant to give a constant, bounded active memory while keeping an expandable long-term store that can be offloaded to slower memory.

The way the two designs work together is the heart of the architecture. The persistent memory bank is split into a short-term window holding the most recent states and a long-term pool of everything older. For each incoming input, the model computes the retrieval indices once, picking the top set of long-term states that look relevant to the current task, and concatenates them with the short-term window to form the active memory state. That state is then decoded into layer-specific key-value caches and prepended to the current input's own states in every attention block. Because the indices are computed once and reused, the active memory is bounded by a constant rather than growing with the conversation, while the long-term pool can be offloaded to slower memory like CPU RAM or solid-state storage. The paper reports that the retrieval and loading take about 64 milliseconds end to end, which is more than an order of magnitude faster than the layer-wise retrieval in a competing native-memory model and far faster than a retrieval-augmented pipeline.

The results are framed as a Pareto frontier, and the headline claim is that MemOnce is the first native memory model to beat the full-context baseline on a memory benchmark suite. Adapting a four-billion parameter model with the MemOnce architecture reduces the memory state cache by a factor of 1313 at a one-million token context, cuts the prefill latency by a factor of about seven, and improves throughput by a factor of about three and a half, while improving overall memory performance by about five and three-quarter points over the full-context baseline. That combination is the interesting one, because prior native-memory methods that achieved the efficiency usually paid for it in accuracy, and this one claims to get both. The authors also train the architecture from scratch at smaller scales, from 150 million to one billion parameters, and report that it matches or beats the standard transformer on validation perplexity even at aggressive compression ratios, The skeptical read has to start with the scale of the headline number. A factor of 1313 reduction in the memory state cache is an enormous claim, and it comes with the usual caveats about what is being compared and at what context length. The number is measured at a one-million token context, which is where the standard transformer's cache is genuinely enormous, so the ratio is amplified by the setting. That does not make it wrong, but it means the efficiency story is strongest exactly at the extreme end, and the authors should be read as making a case for the long-context regime rather than claiming a uniform 1300-fold win at every length. The accuracy claim is the harder one to take on faith, because being the first native-memory model to beat the full-context baseline is a strong statement, and it rests on a suite of memory benchmarks that the authors define and curate. The margin over the baseline is about five and three-quarter points, which is real but not overwhelming, and the comparison to prior memory methods, which the paper frames as large gains, is against systems that are themselves weak, so those larger numbers are somewhat expected.

The more interesting question, and the one the paper gestures at without fully answering, is whether the once-computed retrieval indices are the right trade. Computing the sparse routing once per input and reusing it across every layer and every decoding step is what makes the method efficient, but it is also a point where a different task might need a different set of relevant memories. The short-term window handles the recent context, and the long-term retrieval handles the distant, but the reuse assumption says that the relevant memory does not change much as you decode. That is plausible for many tasks and clearly not for all of them, and the zero-shot transfer to retrieval and reranking is suggestive but not a proof that the indexing is robust across the kinds of continual interaction the architecture is meant for. It is also worth separating the two kinds of efficiency the paper claims, because they come from different parts of the design. The memory-state reduction, the factor of 1313, comes from bounding the active memory so it no longer scales with the conversation length, and that is a structural property of the architecture that should hold across tasks. The prefill latency and throughput gains, the roughly seven-fold and three-and-a-half-fold numbers, come from the once-computed routing and the offloading to slower memory, and those are more sensitive to the hardware and the access pattern, so they are the numbers most likely to move when the system is run on a different machine. The accuracy improvement over the full-context baseline is the number that matters most for adoption, because it is the one that says the bounded model is not a lossy compression of the full one, and the five-and-three-quarter-point margin, while real, is the figure a careful reader will want reproduced on their own data before trusting it. It is worth adding that the architecture is presented in a way that does not depend on a single backbone. The paper shows both an adaptation of an existing four-billion-parameter model and a from-scratch training run at smaller scales, and the fact that the two routes converge on similar behavior is reassuring, because it suggests the bounded-memory design is a property of the architecture rather than an accident of one particular set of weights. The small-scale training is the part that matters most for the long term, since it is the route other groups would actually take, and the report shows it reaches competitive perplexity at compression ratios that would be considered aggressive by the standards of the older memory literature. That gives the method a credible path to larger models without the team having to commit the compute for it yet. On balance, MemOnce is a serious architectural contribution that makes a clean, well-measured case that bounded-memory language models can now match full-context models on recall, and the honest summary is that it closes a gap that was thought to require a trade-off, while leaving open whether the once-per-input retrieval holds up over the long, varied conversations that are the real target.
