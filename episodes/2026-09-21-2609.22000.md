RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents. The first three authors are Shuai Bai, Jiayong Deng, and Yikun Fu, from Alibaba Token Hub at Alibaba Group, with 29 additional authors at the same institution.

Computer-use agents have developed along two separate lines that mostly ignore each other. One line operates applications through the graphical interface, perceiving screens and issuing clicks and keystrokes. The other works through code and the command line, writing and running programs and driving the system through a terminal. A GUI-only agent can watch how a running system behaves but rarely builds the software behind it; a terminal-only agent can author programs but cannot see the interface its actions produce. Real digital work interleaves the two: you operate an application, discover something, then edit the code that drives it, run it, and look at the result. The paper calls agents that sustain that fusion hybrid computer-use agents, and it argues the capability is under-measured because existing benchmarks emphasize one interaction mode or the other.

The framework, RecreationWorld, is built around a single task: application recreation. Given a running reference application, the agent must discover its behavior and build a faithful implementation, with no prescribed workflow. The task has three parts. The input is a high-level prompt, interactive access to the running reference, and an environment with both GUI control and software-development tools. The interaction is open: the agent may move freely among operating the reference, writing code, building and launching its own implementation, and visually checking the running candidate against what it observed. The output is a complete source submission that satisfies the platform's build and launch contract, and only observable behavior is evaluated, not source similarity. Two properties make recreation a good anchor. It is hybrid by necessity: you cannot do it by clicking alone, and you cannot do it by coding alone, because the specification is only discoverable by operating the reference. And it is verifiable by construction: the same running reference that makes the task hard can be exercised by a test generator to produce a fixed hidden suite of assertions, replayed unchanged against every candidate.

The framework ships reproducible environments on five platforms, Ubuntu, macOS, Windows, Android, and Web, plus a unified harness with native GUI control and coding tools. The main benchmark exposes the platform actions as direct MCP tool calls, and the infrastructure distinguishes tool failures from transport failures so that a flaky session does not read as agent failure. For held-out evaluation, the authors introduce RecreationBench: 250 tasks, 50 per platform, spanning different UI frameworks, build systems, and accessibility and automation stacks, with reference implementations withheld where the platform permits.

The evaluation protocol is the part most worth re-using. Test cases are generated along two complementary axes: what they observe and how deeply they interact. Programmatic assertions read exact text, widget state, and action outcomes through each platform's structured accessibility or automation substrate; visual assertions judge layout, color, and canvas content that the substrate does not expose. Each test couples a trigger with its induced response and spans interaction depths from single-step state changes through multi-hop navigation, persistence, and end-to-end computation. Every proposed assertion must first pass on the reference and clear human review before it enters the fixed hidden suite, which is then replayed unchanged against the candidate. A submission that fails to build or launch scores zero; otherwise the score is the fraction of assertions that pass.

The benchmark results on ten frontier models are the sobering part. GPT-6 Astra leads at 58.1 percent overall and is the only model with full programmatic passes on multiple platforms, but full passes cover just 2.8 percent of tasks. Across the board, agents reproduce static interface structure more reliably than interactions or computed outputs, and the applications they generate are substantially smaller and more monolithic than their references. The gap between "looks like the reference" and "behaves like the reference" is the central finding.

The training half of the paper is where the framework earns the "scalable" in its name. The authors use high-quality open-source applications to generate long-horizon recreation trajectories, then train on them. Models at later checkpoints improve across five out-of-distribution benchmarks spanning coding and hybrid computer use, and, notably, they more frequently verify their own rendered outputs as training progresses. The reported transfer gains are +5.8 points for Qwen3.7-Plus and +12.1 points for Qwen-Flash-CPT, measured relative to each model's first checkpoint. The authors are careful to frame these as evidence that recreation builds capabilities that transfer, not as a claim that recreation training is the optimal recipe. The five transfer benchmarks span different shapes of software work, including program construction, repository-level editing, and web interaction, which is part of why the self-verification behavior is interesting: the trained models start checking their own rendered output and execution results before deciding a task is done, rather than stopping at a plausible-looking submission.

The infrastructure numbers matter because long-horizon rollouts are where most environment papers quietly die. Each rollout runs on a versioned, task-isolated worker that pins the graphical runtime, the automation interface, and the build toolchains, and preserves workspace, build artifacts, running processes, and graphical state across the whole explore-implement-verify cycle. The per-rollout wall-clock timeout is 20 hours, so task complexity rather than an infrastructure cutoff determines how long an agent runs. The resulting trajectories are long by comparison to neighboring benchmarks: RecreationBench runs have a median of 282.5 top-level calls with 9.08 GUI-to-code-edit transitions per 100 calls, whereas the closest two-mode benchmark, WeaveBench, records 178 calls and 1.56 transitions per 100. The training data itself is 7,000 trajectories per platform, selected by rejection sampling through the task-specific behavioral verifiers, for a balanced 35,000-trajectory supervised mixture.

The skeptical read. The verification design is the strongest engineering contribution here, and it is directly transferable to your own evaluation harness. Deriving a hidden test suite from a running reference, gating each assertion on reference-pass plus human review, and then replaying it unchanged against the candidate is exactly how you get an objective, automatic, behavior-based signal for anything you can run. That protocol, more than the benchmark numbers, is what I would lift. The 2.8 percent full-pass figure is a genuinely useful calibration: it tells you that even the best current model reproduces behavior on roughly one task in forty, so any pipeline that assumes an agent will recreate a working reference should budget for massive partial credit and expect the failures to concentrate in interactions and computed state, not in layout.

There are caveats to hold onto. Recreation is a specific and somewhat artificial task; real work rarely asks you to rebuild a whole application from a running sample, so the transfer results, while encouraging, are the part I would re-test on tasks closer to your actual distribution. The trajectory analysis is explicitly descriptive, and the authors say so: GUI interaction continuing after implementation begins, and GPT-6 Astra's GUI-centered workflow, are correlations with higher scores, not established causes. The five out-of-distribution benchmarks are the authors' own selection, and the transfer gains are measured against each model's first checkpoint rather than against a fixed external baseline, which makes cross-model comparison harder. Finally, the platform coverage, five operating environments, is impressive, but each platform has its own accessibility and automation substrate, and the programmatic assertions depend on that substrate being faithful; on platforms where the automation layer is thin, the "programmatic" side of the score is weaker than it looks, and the visual assertions carry more of the load.

Bottom line: this is a well-built, verifiable environment for a capability that is real and currently badly under-measured, and its reference-to-hidden-suite evaluation protocol is worth copying even if you never run recreation itself. Treat the 58.1 percent top score and 2.8 percent full-pass rate as the honest current state of hybrid computer use, and expect the transfer gains to shrink on tasks farther from application recreation.
