VibeVideoAgent: Closing the Perceptual Loop for Code-Driven Video Generation, from Xuanyu Zheng, Luoyuan Zhang, and Yancheng Long, at KlingAI Research. The claim: a coding agent that writes rendering programs for video can be made to inspect its own drafts throughout production, and that inspection lifts requirement-compliance scores across three frontier models without any fine-tuning.

The setting is code-driven video generation, where instead of asking a model to render a video, you ask a coding agent to write and run a program that renders one. The appeal is control. A program gives you exact typography, precise data visualizations, synchronized audio, and multi-shot scenes, and it leaves an editable project behind. The failure mode is subtle, and it is the whole motivation of the paper: a program can exit with code zero and write a perfectly valid MP4 in which a character holds a backpack in their hand instead of wearing it, a camera orbits away from the subject, labels collide, or the narration drifts out of sync with the action. None of these raise a runtime error, so a clean exit tells you almost nothing about what the viewer actually sees.

The two obvious fixes both fail. You can feed rendered frames and audio back into the coding session, but that bloats the agent's long-horizon context with high-resolution media until it degrades. Or you can critique only the finished full-resolution render at the end, but by then early design mistakes have propagated into the whole production and become expensive to rewrite. The paper's answer is to run perception in short-lived contexts kept separate from the coder, returning compact, grounded findings instead of raw media. Seven primitives operate on a unified multi-clock representation of assets and drafts. They explore the media from coarse to fine, verify every quoted requirement against evidence from every required modality, compare a draft against a reference or an earlier revision on separate clocks, and so on. The key architectural choice is that the perception context dies after each inspection, so the coding context never carries the frames.

The seven primitives are the implementable core, and they map to four roles. Coarse-to-fine exploration is handled by four of them: describe the media, locate an event on the timeline, inspect a segment, and transcribe speech. Verification is a single primitive that checks a requirement quoted from the brief, with a deterministic check that the evidence covers every required modality, so the agent cannot claim a requirement is met on visual evidence alone when the brief also demands audio. Comparison lets the agent put a draft against a reference or an earlier revision on separate clocks, which is how it catches drift. And a measurement primitive reads stream signals locally. They all operate on a unified multi-clock representation that treats read-only reference assets, zero-duration design stills, shot previews placed at an offset in the final cut, and full cuts in the same structure, and every observation is bound to a hash of the source code that produced it. That hash binding is a small but important detail: it means a finding is tied to a specific version of the code, so a later edit invalidates the finding rather than silently reusing stale evidence. A staged protocol sits on top, with the instruction to test the riskiest decision on a minimal preview first, before committing to a full render.

The evaluation runs on all two hundred thirty-nine tasks of a benchmark the authors call VibeVideoBench, with matched agent runtimes and a fixed perception model. The benchmark is capability-stratified, so the tasks span briefs that stress requirement decomposition, multi-shot synchronization, and typography-heavy layouts, and the ablation subset is a deterministic, treatment-blind slice of thirty-six tasks chosen from native-baseline diagnostics before any ablation run, which removes the obvious leak of tuning the method on the evaluation. The headline numbers are per-model improvements in holistic audiovisual quality. For Claude Opus 5.5, the top-level quality score rises from four point zero three to four point four three, and a lower-level rubric-compliance metric climbs from ninety-eight point eight seven percent to ninety-nine point three five percent. GPT-6 Astra goes from four point zero three to four point two seven, and Claude Sonnet 5.5 from three point nine seven to four point one zero. The largest single gain is in audio-visual synchronization, up to plus zero point five six. The ablations are controlled and each component contributes, and the trajectory audits show a specific trade: the granularity of the code edits governs the balance between rubric adherence and perceptual quality. Local edits, where the agent fixes the specific frame or segment that is wrong, improve both at once. Broad rewrites improve one at the expense of the other.

The mechanics of the perception loop are worth knowing if you plan to build this. Exploration runs at low frame rates by default, and when a coarse pass is uncertain, the system automatically re-queries up to two candidate windows, each padded by a fraction of a second, at eight frames per second, which pins down fast motion onsets and cut points without manual bookkeeping. The segment inspector answers a diagnostic question about a chosen window or pixel crop at four frames per second, and can return up to six evidence frames to the coding agent for visual confirmation. Speech transcription uploads only the audio track and returns timestamped verbatim utterances, which is what makes dialogue cutting and narration alignment tractable. The finding ledger is the audit trail: each finding records the requirement it addresses, the modality of the evidence, the time span, and a hash of the media and the source files, so a defect, a code edit, and its resolution form a checkable chain.

The skeptical pass. First, this is a benchmark the authors built, VibeVideoBench, two hundred thirty-nine tasks, and the perception model used for inspection is fixed across runs, which means the measured gains are partly a function of the judge and the task set being aligned with the method's strengths. The rubric-compliance metric already starts above ninety-eight percent, so the room to move there is thin, and the more meaningful signal is the audiovisual-quality and synchronization gains. Second, the cost is real. Intermediate renders, previews, and re-queries at higher frame rates add compute and latency to every production, and the paper itself lists adaptive scheduling of preview fidelity as future work, which is a candid admission that the current preview strategy is not yet efficient. Third, the whole approach is coupled to coding agents that are already strong enough to write correct rendering programs; the perception loop helps a good coder fix perceptual errors, it does not rescue a weak one. And the behavior depends on commercial vision models whose APIs can change, a dependency the paper flags directly. The evaluation also fixes the perception model across all runs, so the measured improvement is the agent loop's contribution with perception held constant, which is the right controlled experiment but means the absolute quality ceiling is set by whatever vision model you wire in. The gains are also measured on a single benchmark built by the same group, so the external validity of the specific score deltas is harder to assess than the validity of the underlying idea.

The one design choice I would copy into any agentic media pipeline is the context isolation. Keeping raw media out of the coding session and returning compact, hash-bound findings is a general fix for the context-bloat problem that plagues any agent that has to look at what it produced. That idea transfers far beyond video.

Bottom line: a clean, training-free solution to a real failure mode in code-driven video generation, with per-model gains across three frontier coders and an auditable perception loop. I would trust the architectural pattern, verify the benchmark independence, and budget for the extra render cost before adopting it in a latency-sensitive product.
