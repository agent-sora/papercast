Title: Agent Priors-guided Policy Learning
Authors: Puming Jiang, Tianrun Hu, Haozhe Du
Labs: National University of Singapore
Arxiv: 2609.35690
Day: 2026-10-03
Upvotes: 68
Link: https://arxiv.org/abs/2609.35690
---Agent Priors-guided Policy Learning is from Puming Jiang, Tianrun Hu, and Haozhe Du at the National University of Singapore, a two-agent design for robotic skill learning from demonstrations.

The paper is about a specific failure in robot learning from a small number of demonstrations, and it frames the problem as two kinds of generalization that have to work at once. The first is compositional generalization: the robot has to recombine skills it has learned to solve a task it was never shown, a new ordering of familiar operations. The second is skill generalization: the policy behind each individual skill has to keep working when the situation it is applied in is different from the situations it was trained on. The catch is that these two depend on each other, and information is lost between them. Where a skill actually works is determined by the structure the policy was trained with, but the composition layer only ever sees the skill through a separate description, a name, an instruction, a symbolic operator, and that description throws away the structure. So the composer is guessing at the boundary of competence instead of reading it.

The key idea is to make each policy's structural prior part of the interface between composition and the skill. A structural prior is a statement about what a behavior depends on. Their running example: a grasp depends only on the gripper's pose relative to the object, not on the rest of the scene. The prior has a dual role, and that is the whole trick. Built into training, it shapes where the policy generalizes, it constrains the policy to depend only on the relevant variables so it transfers to states it has not seen. Stated in language, it tells the composition layer where the policy applies, so the composer can select and chain skills based on the actual competence boundary instead of a name. They call the system APPL, agent priors-guided policy learning, and it has two agents. A construction agent takes complete demonstrations and segments them into reusable skills, proposes several candidate structural priors for each skill, trains one policy per prior, and verifies them. A runtime agent then selects among those prior-specific policies and composes them toward new task goals, using the language interface. The runtime agent cannot write control code or modify the frozen skill library, and its memory resets between episodes, which keeps the composition step honest.

The first experiment tests the prior's generalization role on MetaWorld, where the policies are trained on a handful of demonstrations per skill and evaluated on states shifted away from the demonstrated ones. The baseline policies, a conditional diffusion baseline and a transformer baseline, are trained on the same demonstrations with no structural prior and see the shifted states for the first time. The APPL policies, one per proposed prior, are trained with the prior baked into the representation. The finding is that the prior-anchored policies hold their success rate under the shift while the no-prior baselines degrade, and that the degradation is largest exactly on the tasks where the relevant structure is object-relative rather than scene-absolute, which is the case the prior is designed for. That is the controlled version of the claim, the prior changes where the policy generalizes, and the shift direction that hurts the baseline is the one the prior predicts.

It is worth being concrete about how a prior is actually implemented, because the paper's contribution is not just the idea but the machinery. A prior is realized through the policy representation, the action parameterization, the architecture, or an auxiliary training loss. Their example is a prior that represents actions in the observed object frame, the rotation and position of the object at the start of an action chunk. The end-effector targets are transformed into that object-relative frame before the policy predicts them, and transformed back before they are executed, with a shared inverse-kinematics module converting decoded end-effector targets into native joint commands. The parameterization is what forces the learned behavior to depend on object-relative rather than absolute motion, so a grasp learned with the object in one place transfers when the object is somewhere else, as long as the relative configuration is within the demonstrated range. Each proposed prior produces a separate conditional diffusion policy, trained with a common recipe, so the runtime has several implementations of the same skill to choose between. The construction agent also overlaps adjacent skill segments around their handoffs, so a successor policy is trained on states that its predecessor actually reaches, including states before nominal completion, which broadens the training support without any new demonstration data. Before freezing, each candidate policy is verified against demonstrated entry states, executed for one and a half times the segment length, and checked against the demonstrated exit condition, and the agent writes a verification report that separates observed outcomes from its inferences, then proposes one more prior per skill using that feedback. The runtime interface for each frozen policy records four fields: the prior description, stating the structural assumption and known limitations; the handoff description, the entry and exit conditions; the support description, the ranges of demonstrated skill-entry states; and the verification evidence. The runtime agent inspects the full interface before invoking a policy, and a call specifies typed arguments, an execution duration, and stop conditions over observed quantities, for example requiring both a gripper width below three centimeters and the grasped object lifted by more than four centimeters.

The second experiment tests coverage and selection together on long-horizon ManiSkill tasks, five of them, where the robot has to exchange blocks between locations, and the test states are shifted so the requested task differs from every demonstrated one. Here the priors are used both in training and as the descriptions the runtime agent reads, and the result is that APPL enables skill compositions that were previously unseen, on tasks where the composition of skills was never demonstrated. This is the stronger claim, because it is not just that individual skills generalize, it is that the composed sequences generalize, which requires the interface to be faithful enough that the runtime agent makes correct selection decisions under distribution shift.

The honest caveats. This is simulation, MetaWorld and ManiSkill, and the paper is careful to say the natural next step is real-robot deployment, where out-of-distribution trials are more expensive and the priors have to be more robust. The priors are proposed by a language model, so their quality is bounded by the model's ability to articulate the relevant structure, and the verification step is what catches bad priors, but verification in simulation is cheaper than verification on hardware. And the demonstration budget is small by design, which is the whole point, but it means the per-skill policies are learned from very little data, so the prior is doing a lot of the heavy lifting that a larger dataset would normally do. There is a further coupling the paper does not fully resolve. The runtime agent reads the prior descriptions to decide which skill to apply and when, so the quality of the selection is only as good as the quality of the descriptions, and a prior that is structurally correct but poorly articulated will still mislead the composer even if it trains a good policy. The verification step checks that the policy respects the prior, but it does not check that the prior is well-expressed for a downstream consumer, which is a gap that matters the moment the system is used by something other than the same model that proposed the prior.

To sum up, this is a clean conceptual contribution with strong simulation evidence: the interface between skill composition and skill learning is where information is lost, and a structural prior, used both to train the policy and to describe it to the composer, closes that gap. The practical takeaway is concrete, if you are building a robot system that has to recombine a few demonstrated skills into new task orders, having a language model propose, train, and verify candidate structural priors per skill, and then selecting among them by development out-of-distribution success, is a real, measured improvement over just training policies and naming them.
