Apodex 1.1: Scaling Agentic Intelligence for Complex Work, by the 71-author Apodex Team, with B. An, B. Li, and colleagues at Apodex, a company that publishes model weights on Hugging Face and runs an API platform alongside its research reports. The technical report frames one capability as the actual target: working capability, defined as sustained, verifiable progress toward a real-world objective. The argument is that general-purpose models reason and summarize adequately, but complex professional work requires sustained interaction with files, information sources, and executable code, plus state maintenance across failures and delivery of artifacts that survive checking. The paper scales that capability along two declared axes, Environment Scaling and Agentic Coordination Scaling, and reports results across professional work, finance, science, mathematics, search, and coding.

Prior agentic systems mostly optimize isolated responses or single-domain loops. ReAct established the reasoning, action, observation cycle; SWE-bench and Terminal-Bench grade repository and command-line work; APEX-Agents grades long-horizon cross-application tasks designed by investment bankers, consultants, and lawyers; deep-research systems handle open-ended information seeking. What is missing in most of that line of work is a single model and runtime where file, search, and code execution compose inside one policy, with coordination treated as a trained behavior rather than a prompted wrapper. Apodex 1.0 was this group's earlier verification-centric agent team. Version 1.1 keeps the architecture and changes three things materially: broader verifiable training environments, an explicit external task board with asynchronous human intervention, and a dedicated synthesis stage separated from team execution.

Start with Environment Scaling, because it defines what the model trains on. The construction principle is stated compactly: forward cheap, inverse expensive. A generator uses latent state or a reference program to construct and solve a world cheaply, then renders only the workspace to the agent, which must recover the relevant path under constraints. Three environment families are built this way. File worlds are profession-conditioned multi-format workspaces where graded quantities must be re-derived by code from authoritative sources or connected through recorded provenance to actual documents; a task is admitted only when independent derivations agree. Search worlds model discovery, acquisition, and evidence synthesis over indexed or open sources, where the gold object includes the source set, claim-to-evidence alignment, and explicit uncertainty when sources conflict, not just a final answer string. Code worlds are stateful sandboxes with repositories and dependencies; shared base images carry interpreters, toolchains, and tests so new worlds are mostly state assembly rather than infrastructure builds. Coverage mixes harvested worlds grounded in real pull requests with synthesized worlds expanded from verified seeds through composition, abstraction shifts, request variation, and adversarial input changes.

Verification gets more machinery than generation, which is the report's most defensible instinct. For harvested code worlds, fail-to-pass tests must fail on the base state and pass after the reference change, while pass-to-pass tests must succeed in both. Synthesized worlds have no external oracle, so passing the reference solution alone is insufficient; the authors additionally test whether a solver can obtain reward without completing the task, and only attacks that succeed in the sandbox count as verifier failures. Scoring is isolated from the solver so it cannot modify its own grader. Every rollout gets an immutable world manifest and a fresh mutable sandbox, and a trajectory is retained only if its initial state is reconstructable, tool execution is isolated, and the verifier replays; replay records include world seed, generator version, tool versions, action sequences, file deltas, and termination reason. Scaling is failure-directed rather than uniform: after each training round, unsuccessful trajectories are analyzed into capability-level deficiencies that become specifications for the next task-construction batch.

The second axis is coordination. Apodex 1.0 decomposed problems internally and dispatched expert subagents. Version 1.1 externalizes that plan onto a persistent task board whose entries record bounded objectives, dependencies, resolution states, assigned agents, and returned evidence. The board sits outside the language-model context as tool-managed state; subagents draw scope from it, completed work attaches back to it, and the runtime re-injects a rendering of it after context compaction. Resolution semantics are worth copying: resolved means the result has been returned and sufficiently checked, not that a process exited. The board also acts as a finalization gate; with planning mode enabled, a final answer is accepted only after every active item is resolved or cancelled, at least one delegated branch has run, and an independent verifier has been used.

Asynchronous human intervention is trained, not bolted on. The policy receives user messages mid-execution and must decide what each one changes: clarifications and priority shifts update board entries and invalidate affected descendants while preserving valid work; messages that materially change objectives or acceptance constraints start a new task contract while carrying forward still-valid workspace state; side questions get short answers without surrendering invested compute. Accepting a follow-up also renews the run's wall-time budget. Training trajectories span requirement clarification, fact correction, priority changes, budget changes, pause-resume-cancel commands, and unrelated questions.

Asymmetric verification narrows the checker's job deliberately. A verifier that inherits the generator's full trajectory anchors on the same assumptions; one asked to redo everything produces a second unconstrained error chain. Instead, each verifier receives a specific claim, its supporting evidence, and the applicable constraint, then attacks that claim through counterexample search, triangulation against independent source classes, atomic checks on names, dates, numbers, and formulas, or compliance testing. Feedback names the contested claim and required repair, so the lead agent reopens one board item instead of absorbing free-form critique. Adaptive Max Team Effort allocates extra independently scoped investigations only to weak, contested, or load-bearing claims, fanning out along different hypotheses or source classes and revising allocation after each return. Finally, synthesis is a separate stage consuming the terminal task board, subagent reports, evidence, artifacts, and verifier findings, never the lead agent's last message. It builds a claim-evidence graph marking which claims are load-bearing, corroborated, disputed, or unresolved; untraceable claims get qualified or dropped, and missing load-bearing dependencies return to the lead agent rather than being papered over.

AgentOS is the substrate underneath. Workspaces split into read-only inputs, mutable workspace, and an outputs collection root, making the delivery contract checkable; publishing requires an exact manifest under a single-writer lease, non-publishers fail closed on writes to outputs, and manifest entries are reconciled against a baseline snapshot so empty or stale files cannot satisfy delivery. Compaction triggers on provider-reported token usage, first evicting old tool-result bodies, then summarizing older trajectory segments only if relief is insufficient. Budgets pair soft deadlines, where agents consolidate findings, with hard timeouts as last resort.

Training is two stages. Supervised fine-tuning covers general reasoning, tool use, search, coding, mathematics, scientific and financial reasoning, professional delivery, and multi-agent coordination, normalized into one stateful interaction schema; domain variants are merged via model soup. Filtering removes trajectories with invalid tool interactions, inconsistent state, or incomplete delivery. Reinforcement learning uses PIVOT-RL: retrospective analysis locates consequential decision points where the model starts down an unproductive strategy, misuses a tool, or fails to revise an assumption; the useful prefix is kept, a localized continuation task gets a short corrective hint that never appears at inference, and hinted continuations are mixed with unhinted full tasks. Completed trajectories enter optimization asynchronously because wall-clock costs vary widely across long-horizon environments.

Now the numbers. The flagship model is reported at 397 billion parameters, with a 35 billion parameter mini. On FrontierFinance, a 220-question rubric-graded investment workflow benchmark, Apodex 1.1 scores 48.7 with ReAct and 54.3 with Agent Team, versus 40.3 for version 1.0, leading their comparison table. On FrontierScience-Research, 60 research-level tasks graded against ten-point rubrics, it reaches 55.0 with ReAct and 63.3 with Agent Team versus 28.3 previously, matching DeepSeek V4 Flash 0731. APEX-Agents goes from 16.5 to 34.4 under ReAct and 38.5 with the team; GDPVal win rate hits 78.8 with Agent Team versus 69.5 ReAct. HLE lands at 56.1 with the team against Claude Opus 5's reported 64.7. Math gains are large but from a low base: IMO 2025 moves from 12.5 to 36.5 across versions, USAMO 2026 from 5.8 to 26.5. On their internal FrontierSearchBench, Agent Team scores 69.1 average, best in their table, roughly halving zero-credit tasks relative to ReAct. Coding is the honest weak spot: Terminal-Bench 2.1 at 70.8 and SWE-bench Verified at 77.7 trail Gemini 3.6 Flash at 91.9 and Claude Opus 5 at 92.2. Their own FrontierResearchBench pass rate is 12.4 percent against 20.6 for the best external system. The mini results are arguably the strongest claim: at 35B parameters, Agent Team lifts FrontierFinance to 50.2, FrontierScience-Research to 51.7, and APEX-Agents to 27.7, described as frontier-band performance at compact scale.

Skeptical notes before adopting anything here. Most headline comparisons mix reproduced and reference numbers; several external GDPVal entries are the authors' own reproductions, and the strongest finance comparison rows are partly internal reproductions. The process-quality evaluation aggregates eight runs for version 1.0 against one run for 1.1, which the authors flag themselves. Environment scaling details stay qualitative; no counts of worlds, rollouts, or compute are given. Bottom line: treat this as a serious engineering blueprint for verifiable environments, externalized planning state, and trained coordination, with benchmark tables to re-run yourself before believing any ranking. The reusable ideas are the forward-cheap-inverse-expensive generator split, sandboxed reward-hacking probes, and the checked task board; the leaderboard position is the least transferable part.
