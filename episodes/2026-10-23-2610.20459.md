The paper is MolLean: A Process-Verifiable Language for Chemical Reasoning, from Jiatong Li and Yatao Bian at the National University of Singapore. This is a neurosymbolic paper in the lineage of work on making language-model reasoning checkable, with the domain being chemistry instead of mathematics. The core problem is that when a language model reasons about molecules, the intermediate steps are just text, and nothing in the pipeline can actually check whether a claimed transformation is legal. You can verify the final answer against a database, but the process is opaque: the model might arrive at the right product by a chain of steps that no chemist would accept. MolLean's answer is to give chemical reasoning a process-verifiable surface: a typed language in which every intermediate molecular state is explicit and checked by a Lean-based kernel, so that each step of a derivation is a well-typed, verifiable transition rather than a free-text claim. The paper evaluates this approach on eight thousand eight hundred matched examples, and it ships an accompanying interface, MolLean-MCP, a stateful model-context-protocol tool that lets an agent execute traces, refine whole traces, and reason interactively.

The design has three layers, and the ordering matters. The first layer is the language itself. A MolLean program represents a chemical derivation as a sequence of explicit state transitions: the current molecular state is a typed term, and each rule application takes the current state and produces the next one, with the typing discipline ensuring that a transition is only accepted if it is a legal chemical operation on that structure. This is the process-verification part: a trace is not just a list of strings, it is a chain of states where each link has been checked. The second layer is the typed witness protocol. When the language model proposes a step, it does not just emit the next state, it emits a witness, a typed justification of the rule being applied, and the kernel checks the witness before accepting the state transition. The separation between the proposed transition and its typed justification is what makes the verification meaningful, because the kernel is checking a formal object, not parsing prose. The third layer is the MCP interface, which wraps the kernel as a stateful tool: an agent can run a whole trace in one pass, receive the set of failing steps, refine the trace and re-run it, or interact step by step, with the state persisting across calls. That statefulness is the part that connects to modern agent tooling, because it means the verification kernel is a first-class tool in the agent's environment rather than an offline checker.

The evaluation is where the paper's scope becomes clear, and it is honestly scoped. The eight thousand eight hundred examples are matched pairs across twelve tasks spanning molecular generation, editing, optimization, and reactions, and the comparison is three MolLean modes against direct chain-of-thought, with Qwen3.6-27B as the generator. Whole-trace refinement beats direct chain-of-thought on all twelve tasks, and the MCP mode, with its stepwise verification feedback, reaches the highest accuracy on the reaction tasks. The soundness number is the one to keep: on ChEBI-20, refined traces reach seventy-nine point zero percent soundness, meaning nearly four in five derivation steps survive the kernel's checks, against whatever the unverified baseline manages. The paper is thirty-three pages, a substantial document, and the language specification is a large fraction of it, which is appropriate for a paper whose contribution is a formal surface.

The language itself has a layered structure that is worth describing, because the layering is what makes one surface cover three different kinds of chemical reasoning. At the primitive level, the language covers graph edits, the small structural operations on the molecular graph, add a bond, remove a substituent, change a connectivity, which are the atomic steps of molecular editing. Above that sit compound transformations, sequences of primitives packaged as single verified operations. And across both, the language has assertions, claims about molecular readouts, properties of the molecule that can be checked against its structure. The kernel sits underneath all of this: the model selects actions and obligations, and the Lean-based kernel checks which transitions are admissible and which native structural predicates hold. The witness protocol is what keeps the evidence types honest. Structural assertions, claims about the graph itself, are checked natively by the kernel. But a chemical claim often depends on a descriptor or on external knowledge, a computed property or a value from a database, and for those, the assertion obtains its typed witness from an external provider, a tool that supplies the measurement. The point of the separation is that construction, transformation, and observation all share one language, but each keeps its own form of evidence, and the kernel knows which kind it is checking. That is a subtle but important design choice, because a single undifferentiated check would either trust the model's claimed measurements or reject every claim that needed one.

The three execution modes correspond to three different operating points on the latency-reliability curve. One-pass trace execution runs the whole derivation in a single shot and then checks it, the cheapest mode, best when you want a quick answer and can discard the trace if it fails. Whole-trace refinement runs the trace, collects all the failing steps, lets the model revise the entire derivation, and re-runs it, which is the mode that won on all twelve tasks, and it trades one extra generation round for a much higher soundness rate. Interactive reasoning through MolLean-MCP is the mode for long horizons: the model receives feedback after each committed action, decides its next move, and rejected actions leave the state unchanged, so the agent cannot accumulate an invalid intermediate state that would poison the rest of the derivation. That last property is the one that matters most for agents, because it turns the kernel into a guardrail that the model cannot talk its way past, and it is the reason the MCP mode reaches the best reaction accuracy, where derivations are long enough that one-pass and refinement modes both suffer.

So what would I trust, and what would I re-verify? I would trust the core design intuition, which is that process verification in chemistry faces exactly the same opacity problem as in mathematics, and that a Lean-based kernel is the right tool for it, because the machinery is well understood and the typed-witness pattern is sound. I would re-verify the evaluation, in two ways. First, the matched-example count is large but the domain is narrow, chemical derivations of a specific kind, and the transfer question, whether the same kernel-in-the-loop pattern works for reaction synthesis planning or for multi-step retrosynthesis, is not answered by this evaluation. Second, the agent integration is the more interesting long-term contribution, and the paper's MCP interface is the part I would want to see stressed under realistic agent behavior: long traces with many refinement rounds, and the failure modes that appear when the model repeatedly proposes invalid witnesses. The kernel will reject them, but the question is whether the refinement loop converges, and the one-pass and interactive results in the paper should be read as the first data point on that convergence question, not the resolution of it.

Bottom line: MolLean is a clean neurosymbolic contribution that brings Lean-style process verification to chemical reasoning, with a typed witness protocol and a stateful MCP interface that fits modern agent stacks. The language and the kernel are the durable artifacts here, and the evaluation is a credible first measurement on matched chemical derivations, with the seventy-nine percent soundness on refined traces as the number to beat. Before generalizing the claim, I would push the same setup onto harder chemical tasks and watch the refinement loop's convergence, because that is where the method either scales or hits a wall.
