Recursive Experiential–Working Memory Evolution for Long-Horizon Agent Harnesses, by Zhaochen Yu of the National University of Singapore, Yingcheng Wu of Stanford University, and Zhenfei Yin of the University of Oxford, with senior authors at Princeton University. The system is called Recuris, and its claim to novelty is a disciplined version of recursive self-improvement: nothing about the language model changes, ever. Instead an external memory-control layer — skills, working-state schema, invocation policy, verification checks — evolves through a validation-gated loop while everything else stays frozen. Across four long-horizon benchmarks and ten models, that layer improves task success in thirty-five of thirty-seven completed pairings, including lifting Claude Opus five from seventy-two point four to eighty-seven point nine percent on a retail tool-use benchmark.

The two design moves deserve separate treatment because they carry separate lessons. First, how memory gets used during a task. Prior experiential-memory harnesses retrieve skills against either the initial instruction or the entire chat history, and both degrade as execution unfolds — instructions go stale, histories fill with completed steps and noise. Recuris maintains instead a compact structured working state where each goal records content, status — pending, done, or blocked — supporting evidence, and any blocker. The crucial discipline is evidential: goals move to done only when an explicit checker predicate confirms completion from the environment's response, not from the model's own claim. Invoking a skill or attempting a tool call is explicitly defined as not being completion evidence. Skill retrieval fires at execution events rather than once per task; their cleverest instantiation intercepts a drafted state-changing tool call before it executes, returns a synthetic not-executed result, retrieves the matching skill, and only then lets the action run with that skill in context.

Second, how memory improves across tasks. Because every step logs the working state, retrieved skills, actions, observations, proposed state updates, and checker decisions, a failed run becomes structured evidence rather than a wall of text. A fixed meta-agent — itself a Claude Code instance that never changes and never sees test data — attributes each diagnosed failure to one of four memory components: a missing or flawed skill, a working-state defect, a badly timed or irrelevant invocation, or a checker that accepted or rejected wrongly. Each implicated component gets exactly one scoped patch, everything else copies through unchanged, and admission requires repairing the failed task without regressing a held-out development set that includes anchor tasks the memory already solves. Attribution here means best repair target, not proven root cause, and the paper says so plainly. The payoff statistic: localizing failures from the structured trace hits sixty-four point eight percent accuracy versus thirteen percent from final outcomes alone. Formally, the evolving object is a four-part tuple: the skill library, the working-state schema and its update proposal, the invocation policy, and the checker set. A candidate round may touch several parts at once, but every edit must trace to a diagnosed failure in the part it modifies — scoping enforced per edit rather than per round.

The experimental hygiene stands out as much as the results. One benchmark-specific skill memory is evolved using only failures of doubao-seed-two-point-zero-pro, a deliberately mid-sized deployment model, then loaded unchanged into every other model from a three-billion open-weight model through frontier APIs. Evaluations run four independent attempts at temperature zero, capped at two hundred steps, with paired task-clustered bootstrap confidence intervals over ten thousand resamples, and daggers mark intervals excluding zero. A harness-contribution ablation shows the memory-control layer with a neutral initial memory is indistinguishable from zero on four target models, so gains above it belong to what evolution learned. Sixty-five of those pairings are worth scanning individually: the deployment model itself jumps twenty-three point three points on tau-two-Retail and sixteen point eight on SkillFlow; frontier names gain too — GPT-five-point-six-Sol plus seventeen point eight on Retail, Opus five plus fifteen point six reaching eighty-seven point nine, which is nine point seven above anything any model achieves there without the system. The build protocol explains why these comparisons hold. For each benchmark exactly one skill memory is evolved, using only failures of the deployment model running the benchmark's own reference agent unmodified; the meta-agent, itself implemented as a Claude Code session, is identical across rounds and benchmarks and never sees test data, and the splits separating evolution, gating, and held-out evaluation were fixed before any run. Success demands full environment reward — an episode that ends in agreement with a simulated customer while leaving the underlying database unchanged scores as failure — and attempts run at temperature zero, four per cell, capped at two hundred steps and ten consecutive tool errors, with paired task-clustered bootstrap intervals over ten thousand resamples deciding which deltas count.

The analysis sections deliver the kind of findings most papers omit. Stratifying tasks by intrinsic horizon, the advantage does not decay — it grows, reaching roughly thirty-two points on the longest bucket. Why? Not retrieval: read-action recall stays between eighty-eight and ninety-seven point nine percent for every variant at every length, so agents always find out what to do. The failure is execution: the base agent finishes forty-two percent of write-requiring episodes having performed none of the required writes, versus sixteen percent under Recuris, and the first correct write happens at the same median turn everywhere — the state tracker changes whether the agent acts, not when. Quartile boundaries come from intrinsic completion length pooled across all variants, so an early-quitting agent cannot migrate itself into easier buckets — the kind of circularity check most stratified analyses skip. The component ablation quantifies it: adding a skill library alone is worth an interval indistinguishable from zero, the verified working state alone adds twenty-three point nine points, coupling both tops out at twenty-five point four over baseline, and a model-controlled variant holding the same library but injecting all of it every turn sits eighteen points below Recuris — availability isn't the mechanism, deciding when to invoke is. That pure-library regime also carries thirty-one hundred extra tokens at first call and costs forty-six percent more per success. Skill delivery itself carries remarkably little machinery. Call-time invocation intercepts a drafted state-changing tool call before it executes, answers it with a synthetic not-executed result, retrieves skills keyed to the named tool, and lets the action be drafted again with the skill present in context; boundary invocation instead fires once at an attempt's opening turn under a predicate on the working state. Trigger predicates and retrieval keys are themselves evolvable components, subject to the same diagnosis-and-gate loop as everything else. Domain structure even decides which internal mechanism matters: removing pre-execution write review costs the airline domain thirteen and a half points while costing retail essentially nothing; removing the status-board presentation costs retail seventeen point three and costs airline nothing — a genuine double dissociation — while the after-the-fact truth guard, despite rejecting one hundred seventy-two bogus completion claims, never matters anywhere because you cannot audit a write that already executed back out of existence.

Equally instructive is where the cross-task loop refused to work. Terminal-Bench has no shared structure across tasks, and thirteen evolution runs admitted zero patches; there the paper falls back to single-task adaptation with retry budgets matched against a paired control. And six of thirty-seven pairings are regressions or nulls — mostly small airline deltas whose confidence straddle zero, honestly displayed. Skeptical residue: memories evolve on one model's failures, so transfer to stronger models rests on what models share rather than idiosyncrasies, an assumption tested but only within this model zoo; benchmarks are simulated environments with programmatic verifiers; and calling bounded memory-layer improvement recursive self-improvement will strike some readers as branding, though the restriction to interpretable component-scoped edits is precisely what makes the loop auditable. Bottom line: the strongest evidence yet that agent self-improvement can be made safe, local, and measurable by evolving only an evidence-gated memory-control layer around frozen weights — and the write-recall diagnosis, that long-horizon failure is forgetting to act rather than failing to know, may prove more valuable than the framework itself.
