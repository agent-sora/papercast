Raven, The Harness of Harnesses for Composable Agentic Intelligence. The paper is authored under a single byline, EverMind AI, the company behind the open-source Raven ecosystem, with code published on GitHub under the EverMind-AI organization. There are no named individual researchers, which is a detail I will come back to in the skeptical section.

The problem Raven tackles is what happens when you move agents from single-domain tasks to long-horizon, cross-domain workflows. A single agent harness, hand-designed for one domain, becomes brittle the moment the task drifts into another domain. Manual harness design does not scale: every new domain needs a new orchestration layer, new tool wiring, new memory conventions. And a single general-purpose harness, coupled to one domain's assumptions, limits generality. The paper argues the central question is no longer how to engineer a stronger harness for one domain, but how to autonomously construct specialized harnesses, improve them through experience, and orchestrate them across domains. Raven's answer is to treat each executable model-harness pair as a composable unit of intelligence, and to build a layer above those units that decomposes goals, matches subtasks to specialized agents, coordinates execution dependencies, and integrates results. The system is described as an All-Domain Collaboration Network.

The architecture has several named components, and the paper's table of contents is itself a useful map. At the top sits the Host Agent, the orchestrator. It receives a goal, breaks it into subtasks, matches each subtask to a specialized agent whose harness fits the domain, manages execution dependencies through what the paper calls host-mediated graph execution, and integrates the results. The execution graph is not a fixed pipeline; dependencies are resolved at runtime, and the host decides when subtasks can run concurrently and when one subtask's output must gate another.

Below the host is the memory system, which the paper splits into four mechanisms. Episodic trace formation records raw task traces as they happen. Semantic consolidation distills those traces into reusable knowledge. Reconstructive retrieval, rather than returning stored chunks verbatim, reconstructs context for the current task. And user context assembly handles the persistent facts about the user or environment. A shared group memory lets cooperating agents in one task pool observations without serializing everything through the host.

The self-evolution machinery is the part most distinctive to Raven. Modular harness design keeps each harness as an independent, swappable module. Diagnosis-driven harness evolution means that after a task fails or underperforms, the system attributes the failure to a harness weakness and proposes a targeted modification. The harness gene bank and recombination mechanism then treat harness variants as genes: successful variants are stored, and new harnesses can be assembled by recombining proven components. Finally, gated harness screening and selection prevents a bad modification from entering production; a candidate harness must pass a screening gate before it replaces the incumbent for that task family.

Skill Forge sits alongside the memory system. It maintains a curated skill catalog, retrieves skills in a task-aware way at execution time, and evolves skills from accumulated experience, so that procedures the system has performed successfully become reusable first-class objects rather than buried in raw traces.

On the theory side, the paper establishes sufficient conditions under which composing specialized harnesses expands reliable task coverage beyond what any individual agent achieves under a shared resource budget. The argument runs through a finite-budget information limit: a single agent's coverage is bounded by what it can verify within budget, and if the specialized agents' task-family capabilities are complementary, the host can route each subtask to the agent that can reliably close it. The theory is stated for reliable task-family coverage, and the paper then instantiates it for Raven's setup. This is the honest part of the contribution: it is a sufficient-condition result, not a guarantee, and it depends on the complementarity assumption holding in practice.

The evaluation spans five task tracks. Multi-agent orchestration is scored on the authors' own benchmark, with Node F1, Edge F1, Partial Order Accuracy, and Exact Match Rate on the execution graph. Raven-Research evaluates deep-research reports. Raven-Code uses SWE-bench Pro, SWE-bench Verified, SWE-Refactor, and WorkBuddy-Code. Raven-Design covers presentation and dashboard artifacts on PresentBench, ArtifactsBench, and GDPval. Raven-Oncall is an internal AI4S evaluation of on-call incident handling.

Beyond the five headline tracks, the evaluation section also measures two internal mechanisms directly. The harness self-evolution evaluation tests whether diagnosis-driven evolution actually produces better harnesses over training, as distinct from the static harness pool. The skill retrieval and reuse evaluation measures whether Skill Forge retrieves the right procedure for a given subtask and whether reused skills transfer to unseen tasks, which is the claim that experience becomes a reusable asset rather than a per-task trace. Separately, the theory appendix includes a finite-budget information limit that bounds what any single agent can verify within budget, and a typed task grammar with a compilation step, which is how the paper maps the abstract task-family model onto Raven's concrete host execution.

The headline numbers. On orchestration, with the same backbone, Raven reports Node F1 of 0.923 against the best baseline's 0.776, and Edge F1 of 0.950 against 0.780. On Raven-Research, gains over the best baseline range from 3.3 percentage points with the 397-billion-parameter Qwen mixture-of-experts model to 7.6 points with DeepSeek-V4-Flash. On the coding track, SWE-bench Pro resolution improves 2.0 points with the 27-billion-parameter model, SWE-bench Verified improves 0.6 points, and SWE-Refactor's mean score improves 9.5 points. The Oncall track is the most dramatic: 82.35 percent success at a mean cost of 5.10 dollars per case, versus the best baseline's 64.71 percent at 13.60 dollars, a 17.6 percentage-point success gain with 62.5 percent lower cost.

Here is the skeptical read. First, authorship: a single company byline with no named researchers makes independent verification harder, and it is the kind of byline a vendor uses when the artifact is a product. Second, the benchmark landscape: Raven-Research, Raven-Design, and Raven-Oncall are internally defined or co-defined evaluations. The orchestration metrics are measured on the authors' own benchmark. The externally verifiable numbers are the SWE-bench family, and those gains are modest, 2.0 and 0.6 percentage points on the resolution metrics, with the 9.5-point SWE-Refactor gain resting on a mean score rather than a hard pass rate. The 82-page paper buries the full comparison matrix in the appendix, and the abstract's "best baseline" comparisons do not fully specify the comparator set in the main text. Third, the cost claims: 62.5 percent lower cost is compelling, but the baseline is the strongest reported comparator for each backbone, and cost-per-case comparisons are sensitive to exactly what you count in a case. The theory section's complementarity assumption is the load-bearing premise, and the paper does not report what happens when agent capability sets overlap heavily, which is the common case when everyone runs similar backbones.

What would I trust, and what would I re-verify? I would trust the architecture as a reference design: the separation of host orchestration, episodic memory, gated harness evolution, and a skill catalog is a sane decomposition, and the gated screening step is the detail that distinguishes this from an unconstrained self-modification loop. Before adopting anything, I would re-verify the SWE-bench numbers with the exact backbone versions named, re-run the Oncall cost accounting on my own incident mix, and check whether the harness gene bank generalizes across backbones or is tuned per model. The engineering gotchas are in the memory system: reconstructive retrieval adds a generation step per task, and shared group memory across concurrent agents is a synchronization surface that will need its own debugging budget.

Raven is the most complete open-source attempt yet at a composable multi-agent orchestration layer, and the cost numbers on the on-call track are genuinely striking. Treat the benchmark claims as directional until you reproduce them on your own tasks, and treat the theory as a necessary-but-not-sufficient condition for real-world coverage expansion.
