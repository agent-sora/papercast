The question the paper is answering is a paradigm question, and the
framing is specific. Agentic systems have recently become the dominant
paradigm for formal theorem proving, and they achieve strong performance
by coordinating multiple models and tools, and the paper's observation is
that the existing approaches often rely on task-specific pipelines and on
trained formal provers, and those two dependencies are the part that
limits them, because a task-specific pipeline is a system that is built
for one kind of problem and does not transfer, and a trained formal
prover is a model that is specialized to the proving task and is not the
general reasoning system it is built from, and the two dependencies are
what limit the flexibility and the reproducibility of the existing
approaches. The paper's contribution is a paradigm, and the paradigm is
specific, it is to directly use a general coding agent as a formal
mathematics reasoner, and the general-coding-agent property is the part
that matters, because a general coding agent is a system that is already
built, already trained, already deployed, and already good at the kind of
work that formal theorem proving requires, which is reading a proof state,
writing a tactic, checking the compiler output, and trying again, and the
paper's argument is that the coding agent does not need to be specialized
to the proving task, it needs to be given the tools, and the tools are
the part that make the general agent a formal mathematics reasoner. The
tools the paper describes are the part a reader should hold onto. The
first is the set of formal-mathematics tools, the goal querying, the Lean
diagnostic messages for obtaining authoritative verification results, and
the tools that let the agent read the actual proof state rather than
guess at it, and the paper's point is that these tools liberate the model
from guessing about the proof state, and the guessing is the part that a
prover without the tools has to do, and the tools replace the guessing

Bottom line: this is a well-motivated paradigm paper that proposes to
directly use a general coding agent as a formal mathematics reasoner,
with a set of formal-mathematics tools for goal querying and diagnostic
messages and a code-execution loop for instant compilation and strategy
exploration, and the result is that with Claude Opus four point five as
the base model the system solves all twelve problems in Putnam twenty
twenty-five, matching the best closed-source system, and it demonstrates
generality by formalizing the Brascamp-Lieb inequality in a collaboration
with a mathematician. The open question is how much of the result is the
agent and how much is the base model, whether the twelve-problem Putnam
set is memorizable, whether the tooling is released, and whether the
system runs on an open model, because the open and general in the title
are two different claims that depend on different parts of the system.
