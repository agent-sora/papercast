QDA, by Xingyang Li, Tianlang Zhao, and Song Han, from MIT and NVIDIA, is a system in which a large language model agent designs post-training quantization recipes for each model and precision it is given. The premise is that the best quantization recipe differs across models and bit precisions, so experts today hand-design one per model, and that hand design does not scale: between October 2025 and September 2026, more than 90 open-weight models with over 10 billion parameters were released, which at the four precisions the paper studies would need over 360 hand-written recipes. Across four reasoning models, QDA improves average accuracy over the strongest public recipe by 0.9, 1.4, and 2.2 percentage points at 4-bit weight 16-bit activation, 4-bit 8-bit, and 3-bit weight 16-bit activation, respectively, using 64 GPU-hours per search. On the 320 billion parameter mixture-of-experts model GLM-5.3-Flash at FP4 weights and FP4 activations, a single 6.5 hour search recovers 98.3 percent of the FP8 model's accuracy, against 96.9 percent and 96.3 percent for the vendor checkpoints released by NVIDIA and Red Hat AI.

The background matters here, because quantization is a stack of small error fixes. Post-training quantization compresses a trained model by mapping groups of values to low-bit codes with a scale and a zero point, and different published methods fix different sources of the resulting error. Because the errors are complementary, methods can be stacked, and a combination often beats any single method. A quantized checkpoint is therefore produced by a recipe: the stacked methods, their settings, and their calibration data. The problem the paper documents is that the winning recipe is model-specific. With 4-bit weight-only quantization, the most accurate public recipe is ParoQuant on Qwen3.5-9B but GPTQ on DeepSeek-R1-Distill-Llama-8B. On Qwen3.5-9B alone, AWQ beats GPTQ in 4-bit but loses to it in 3-bit. So there is no transferable answer, and the only way to find the best recipe for a new model is to try candidates on that model. NVIDIA's ModelOpt keeps a separate hand-written recipe for each of 28 models, recording model-specific decisions like which modules to leave in BF16.

Two practical obstacles stand between an agent and doing this search itself, and QDA's design is a response to each. The first is evaluation cost. A reasoning model writes thousands of tokens per answer, and each problem must be sampled many times, so a full evaluation of one quantized checkpoint takes up to 86 GPU-hours. At that cost, a search can afford only a handful of candidates, which is not a search. QDA's answer is a proxy metric: the KL divergence between the candidate's next-token distributions and the original model's, measured on reference traces that the original model itself wrote. Because the original model's distributions are cached, scoring a candidate takes minutes, which the paper says is 350 to 990 times cheaper than a full evaluation. The agent then runs full long generations on only the promising candidates, to catch rare failures like repetition loops that a distributional score would miss. The second obstacle is build cost. Most published quantization methods ship as separate research codebases, so a recipe that mixes several of them must be ported by hand to each new architecture, including linear-attention hybrids and fine-grained mixture-of-experts. QDA implements 21 public post-training quantization methods in one library behind a common interface: every method takes a quantized checkpoint as input and returns one, so the agent can stack them in any order without porting code. A harness runs the search without human supervision and keeps the test benchmarks and reference traces out of the agent's reach, because a recipe tuned on the test set would score higher without being any better.

The results, in the parts of the paper I could verify, are modest in absolute terms and consistent in direction. On the four main reasoning models, which span dense transformers, linear-attention hybrids, and mixture-of-experts, QDA beats the strongest public recipe by the 0.9, 1.4, and 2.2 point margins I gave earlier, at a cost of 64 GPU-hours per search. It also beats greedy search and ASHA, a classic bandit-style selection method, by up to 1.2 points at 4-bit 8-bit and 3-bit 16-bit when those methods search the same library with the same budget. The cleanest control experiment is the one where the same agent is given NVIDIA's ModelOpt toolkit and its recipe-search skill instead of QDA's library and evaluator: even though the ModelOpt agent selects candidates directly on the test benchmarks, it lands 0.5 to 1.3 points behind QDA, and on Qwen3.6-35B-A3B it is below the best public recipe at the two lower precisions. The authors read this as the gain coming from the search flow and infrastructure rather than from the agent model alone, which is the right reading. On the 320 billion parameter GLM-5.3-Flash, one 6.5 hour search on 16 GB300 GPUs, with about 69 dollars of agent tokens, recovers 98.3 percent of FP8 accuracy on a four-benchmark average of 77.7 percent, against 96.9 and 96.3 percent for the two released vendor checkpoints, and QDA's checkpoint is also the smallest, at 183.6 gigabytes against 190.4 and 184.3, because it quantizes more modules. Every QDA checkpoint runs on the existing serving kernel of its format with no inference overhead.

Where I would apply skepticism. First, the margins on the main four models are small: sub-2-point average gains over the best public recipe are real but not a step change, and the paper is candid that on some individual model and precision pair, QDA is actually below a single strong method, for example 0.2 points under GSQ at 3-bit 16-bit. The value is in the automation and the uniformity, not in a new quantization breakthrough. Second, the proxy metric is doing a lot of work. The KL divergence on reference traces is a standard and sensible surrogate, but the entire search quality depends on the proxy ranking candidates the way the true accuracy would, and the paper's own admission that it needs to run full generations on promising candidates to catch repetition loops is an acknowledgment that the proxy has known blind spots. Third, the 86 GPU-hour full evaluation and the 64 GPU-hour search budget are both large; this is a tool for teams with serious GPU access, not a drop-in for a small lab, even if the 350 to 990 times speedup on scoring is a genuinely large number.

Still, the framing is the useful contribution. The paper shows that recipe design is a legitimate agent task precisely because it proceeds by trial and error, and that the two things blocking agent-driven search, expensive evaluation and incompatible codebases, have clean engineering answers: a cached-distribution proxy score and a unified method library. The control where the same agent does worse with the industry-standard toolkit is the most informative result in the paper, because it separates the infrastructure from the model.

The four evaluated precisions are specific, and the paper's table spells them out: W4A16 is INT4 with group size 128 and asymmetric scales over BF16 activations, run on the Marlin kernel; W3A16 is INT3 with group size 128 symmetric scales, with attention heads and embeddings kept at INT4 with group size 64, on the Humming kernel; W4A8 is INT4 with group size 128 symmetric scales and per-token FP8 activations in the E4M3 format on a CUTLASS kernel; and the NVFP4 setting is 4-bit floating point in the E2M1 format with group size 16 and FP8 scales for both weights and activations. The reason the precision matters so much is that at W4A16 and W3A16 the kernel dequantizes weights back to BF16 in registers, which saves memory traffic but not arithmetic, whereas at W4A8 the activations are quantized too, so the tensor cores do the multiply in low precision and the compute-bound prefill and large-batch decoding actually speed up. The paper's scale argument lands here: over 90 open-weight models with more than 10 billion parameters were released in the twelve-month window it cites, which at four precisions means over 360 hand-written recipes that do not exist today and that the agent system exists to replace.

My verdict: QDA is a well-executed systems paper with honest, modest, and consistent results, and its strongest finding is that the search harness matters more than the agent inside it. It is a credible blueprint for agent-driven quantization if you have the compute. Read it if you quantize production models; the numbers will not shock you, but the recipe is reusable.
