The paper is called "Sketchpad: certified exact arithmetic with a small vision-language model." It is a single-author paper by Mostafa Mohsenvand, at the MIT Media Lab.

The problem starts from a distinction most people gloss over. Large language models answer most long-arithmetic problems correctly, but that accuracy is measured on samples. It is an estimate, and the remaining errors are silent. The model gives you a confident-looking wrong number and there is no flag to tell you it is wrong. In their comparison, GPT-6.1 Sol answered 217 of 220 problems correctly, and its three errors, on sums of 300 and 1,000 digits, were completed answers well within the token budget, in exactly the same form as the correct ones. Tool use is the standard workaround, it is exact, but it moves the computation outside the network, so you have handed the job to a calculator. The paper's question is whether you can get a guarantee, a guarantee that holds for all inputs of all lengths, from a network that does the computation itself.

The key insight is classical and the paper says so. A guarantee over unboundedly many inputs requires that the behavior on infinitely many inputs be fixed by finitely many facts. That is true when each step of the computation reads only a bounded view of an external memory and no other state passes between steps. The steps then range over a finite set of views, and a network that is correct on each view is correct on every run of any length. This underlies Moore's analysis of experiments on finite automata, the verification of learned recursive programs, and a recent certificate for universal computation by language-model decoding. There is also a converse, and it is the important warning: if a step may read the steps before it, as in chain of thought, then no finite test suffices. Chain of thought is exactly the architecture that makes this kind of certification impossible, because the state keeps growing.

Sketchpad is built to make the hypothesis hold by construction for a pre-trained vision-language model. There are three parts. A sheet holds all the state. A model maps one view of the sheet to the outputs of one step. And a runtime moves the view and writes the outputs. The requirement driving the design is that the input of each step must come from a finite set that can be listed in advance.

Concretely, the model is Qwen3.5-0.8B, which combines a vision encoder with a 24-layer language model in which six layers use full attention and eighteen use Gated DeltaNet. The only trained component is a rank-16 LoRA adapter on 150 projection matrices, with 10.2 million parameters, about 1.2 percent of the model. They call it the arithmetic adapter. The sheet is a grid of 32-pixel cells, each blank or holding a digit from a fixed glyph set. A view is three cells, rendered as a strip 32 by 96 pixels, which the vision encoder reads as three image tokens. A step's prompt is an operation token, the view, an equals sign, and two placeholder tokens, and the model reads its three outputs at those positions in a single forward pass: a digit, a carry or borrow, and the next operation. The prompt contains nothing else. They call this the pinned-sheet policy, and under it the model's output is a function of the view alone.

For each arithmetic operation there is a table listing every view the operation can meet, with the correct outputs. The addition table has 242 views. The five operations of long multiplication have 1,553. Subtraction has 242. Estimating a quotient digit has 400. Decrementing an estimate has 9. Adding those up, the total set of views is 2,446. That number is the whole game, because it is the finite set that a certificate must check.

The certification is where the paper earns its title. They define the margin of a view as the smallest lead, across output positions, of the correct token's logit over any competing token. A view passes if its margin is positive. Then Theorem 1 says the model's run from every starting configuration equals the reference run at every step if and only if the model agrees with the table on every view the reference run presents. In particular, if every view has a positive margin, then every run of every length is exact. Theorem 2 is the necessity result: if a step's context also retains the earlier steps, as in chain of thought, then there exists a two-state table and a family of decoders such that for every finite set of tests, some decoder passes every row and every test, yet errs on a longer run. So the restriction to bounded views is not a convenience, it is what makes certification possible. Theorem 3 handles the fact that the model runs in floating point, not exact arithmetic: if the logits on the real execution path stay within a tolerance of the reference logits, and each margin is larger than twice that tolerance, then every run is still exact.

They then do the actual check on the hardware that runs the model, an Apple M4 laptop GPU, executing in 16-bit precision through ONNX Runtime on WebGPU. All 2,446 views pass. The smallest margin is 3.02 logits for addition, 6.52 for multiplication, and 4.61 for the calculator tables. By Theorem 3, a margin of 3.02 tolerates any change of the logits smaller than 1.51. They verify that batching, which changes the 16-bit logits, keeps the margins safe: with every view placed in random batches of up to 32, no logit moved by more than 1.09 and no margin by more than 0.64, so the batched path satisfies the robustness theorem. The full check takes 3.5 minutes on the M4. They note that a 4-bit quantized decoder moved some preliminary margins from plus 9.4 to minus 8.9, which is exactly the kind of silent failure the certificate is designed to catch.

The certified model then performs signed addition and subtraction, long multiplication and division, square roots, and greatest common divisors, at arbitrary length. In a pre-registered browser test of 200 problems, run one at a time on the M4, all 200 were exact. In a comparison of 220 problems, sums of up to 1,000 digits and products of up to 20 digits, Sketchpad solved 220 of 220, while the strongest of ten other models, GPT-6.1 Sol, solved 217. Because the certified procedures compose, a symbolic runtime built on them solves, expands, and factors polynomials with every number computed by the model. And a scalar gate on the adapter restores the base model exactly when the sheet is not in use, so the arithmetic capability does not degrade the model's general behavior.

Now the skeptical read. This is the strongest kind of result in the paper, a formal, Lean-checked certificate that a specific network is exact on a specific set of computations, and that is rare and worth taking seriously. The theorems are clean and the necessity result, that chain of thought makes certification impossible, is a genuinely important conceptual claim. But the scope is narrow in ways that matter. The guarantee covers the model's steps and is relative to the runtime, and the runtime's layouts, outer loops, and reference procedures are conventional code that are not themselves formalized in Lean, so the certification rests on the runtime being correct, which is asserted step by step rather than proved. The certified operations are the classical pencil-and-paper procedures, so this is certified arithmetic, not certified reasoning, and it does not extend to the kind of multi-step mathematics where chain of thought is the whole point. The certificate is device-specific to the 16-bit M4 path; a different GPU requires recomputing it, which is the right design but a real operational constraint. And the model is 0.8 billion parameters, so this is a proof of concept for a small model with a narrow adapter, not a claim that frontier models can be certified this way. What I would trust is the central theorem and the necessity result, that exactness over unbounded inputs reduces to a finite checkable condition precisely when steps read only bounded views. What I would re-verify before building on this is the correctness of the runtime it is relative to, the generality of the certificate to other operations and other hardware, and whether the approach scales to problems where the intermediate state cannot be kept within a fixed-size view.

The bottom line: Sketchpad is a clean and genuinely novel result showing that a small vision-language model can be formally certified to do arbitrary-length integer arithmetic exactly, with a Lean proof that the guarantee holds and that chain-of-thought architectures make such certification impossible. It is a proof of principle for certified neural computation, tightly scoped to bounded-view procedures and a specific device, but the underlying theorem is the important contribution.
