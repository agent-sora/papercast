MobileMem: Learning from a Year of Mobile Experiences, by Xinle Deng, Yida Xue, and Xiangyuan Ru, from OPPO and the OpenKG community. The argument is that agent memory research has been solving the wrong problem in the wrong place. Cloud memory benchmarks assume infinite storage, centralized databases, and conversation-shaped data. Real deployment for next-generation assistants happens on phones, glasses, wearables, and cars, where memory must be multimodal, cross-app, temporally continuous, and built under hard storage, power, latency, and privacy constraints, with raw data never leaving the device. MobileMem is both a benchmark and a framework for on-device long-term memory grounded in roughly one year-scale collection of mobile experiences, and its evaluation results are unflattering to essentially every current memory system. If you build personal assistants, this is a requirements document disguised as a paper.

The architecture vision first, because it shapes the benchmark design. Rather than screenshot-scraping everything the user does, the authors observe that modern apps already function as specialized memory systems: browsers keep timestamped searchable histories, finance apps aggregate transactions into monthly summaries, notes apps store structured records. They formalize a two-layer composite ecosystem. A system-level memory layer attached to the assistant acts as a blackboard holding global user state, cross-app preferences, and behavioral abstractions. Application-specific memories act as knowledge sources doing cognitive offloading, filtering transient interface noise like scrolls and page switches and forwarding only meaningful events through a standardized protocol with explicit permission control. Users define which apps contribute; apps define what is safe to expose. The two instantiated benchmarks simplify this vision into testable settings.

MobileMem proper covers the text setting: seven app types, including Bill, Voice Recorder, Screen Memo, Document, Note, Calendar, and To-Do List, integrated with the assistant via message templates, where record creation events flow to the memory layer as structured text. MobileMem-Omni is the harder multimodal sibling: sixteen users, eight English and eight Chinese speakers recruited as real volunteers plus eight synthetic profiles, whose screenshots are shared with an assistant operating independently of the apps. Scale numbers for Omni: one thousand five hundred eighty-nine total events, average context length one point seven two million tokens per user, about two hundred three sessions per user, forty-eight dialogue turns per session, over one hundred fifty-five thousand turns total, nineteen thousand sixty images, and seven thousand four hundred fifteen question-answer pairs across seven categories: single-hop, multi-hop, knowledge update, temporal reasoning, implicit preference, abstention, and visual reasoning.

The synthesis pipeline, called KEME for knowledge-guided experience synthesis, deserves attention because long-horizon personalized data cannot simply be collected. It starts from prior knowledge: volunteer interviews, real but anonymized trajectories from OPPO phones where only usage statistics and metadata were recorded to comply with service agreements and privacy standards, PersonaHub seeds for synthetic expansion, and a personal relationship graph with generated portrait images. Then four agents alternate top-down planning and bottom-up evolution. A Knowledge-Guided Planner builds a hierarchical temporal event graph decomposing a year into coarse life events down to sessions, with expansion depth capped at two for the text benchmark and events per graph bounded between two and fifteen. A Knowledge Anchor Grounder pins immutable real sessions onto compatible event nodes whose time intervals fully contain the anchored session, revising the graph when no compatible slot exists, and propagates compatibility constraints downward through a summarized event-level context capped at eight thousand tokens so synthesized content cannot contradict anchored facts. An Experience Realizer writes concrete sessions consistent with inherited constraints, while an Experience-Driven Reviser adjusts future events based on newly synthesized outcomes, closing the loop; the Omni variant omits this feedback step purely for cost since its trajectories exceed two million tokens. Persona attributes carry version histories with message-level evidence links, so preferences update only when experiences imply genuine state change. Quality control combines automatic validation, human sampling of trajectory segments, multimodal checking of generated images including face-recognition verification against reference portraits using InsightFace, rejection and regeneration of failing images across multiple generation models, and LLM verification of QA evidence sufficiency with near-duplicate filtering. One honest detail: manual inspection surfaced minor numerical inconsistencies like drifting prices and ages of non-user participants, retained deliberately as natural noise resembling plausible user error.

Results, and they are rough on incumbent systems. In the text benchmark evaluated with Qwen3.5 as judge model, A-MEM leads overall at seventy-nine point six eight percent with GPT-4.1-mini as backbone and HippoRAG2 close behind at seventy-eight point eight five, both beating naive RAG at thirty-seven point two three and plain long context at fifty-four point five one, where long context means stuffing a hundred twenty-eight thousand token window. Under GPT-5.4-mini backbones, MemOS takes the lead at seventy-four percent overall while most systems improve slightly; EverMemOS spends the most tokens, over eleven thousand per trajectory, and A-MEM's construction cost more than doubles under the newer backbone because it extracts more keywords per memory unit. The pattern behind the ranking: systems preserving original information without aggressive compression win, because many questions hinge on fine-grained details that lossy summarization discards. Error attribution on sampled failures shows distinct failure modes per system: thirteen of twenty long-context failures were update errors from window overflow, naive RAG failed mostly on retrieval misses, Mem0 lost facts during extraction because its prompt focused on user messages and missed assistant and app content, and EverMemOS failed mainly at answer generation despite good construction and retrieval, including a reranker that discarded already-retrieved target documents and a sufficiency check that triggered extra retrieval rounds injecting distractors. Every system shared one weakness: answer generation distracted by irrelevant retrieved memories or overgeneralizing precise facts. Adversarial questions produced the sharpest inversion: LangMem, the weakest system overall at around twenty-five percent, scored best on them, because strong retrievers confidently surface weakly relevant distractors that convince the model an answer exists.

Task-type gradients tell implementers where the pain lives. Performance falls steadily from single-hop questions through multi-hop to query-focused summarization, which additionally requires compressing evidence into concise answers. Temporal reasoning stays weak across the board, evidence that current memory stores fail to preserve event ordering among timestamps. Abstention is worse still: in Omni, most methods score below twenty percent, meaning systems fabricate rather than admit ignorance when information is missing. Multimodal results compound the problem: EverMemOS with GPT-5.4-mini tops out at thirty-nine point four one percent judge score against LightMem at thirty-three point eight, multimodal long context beats caption-based pipelines on visual reasoning twenty-one point nine versus twelve point one six percent, and adding captions to text retrieval actually degraded non-visual questions by four point four points while helping visual ones by three and a half. A persistent English-over-Chinese gap appears across every method, attributed to memory mechanisms designed and optimized for English first, and short-term events prove hardest since they lack contextual redundancy, with scores improving monotonically as event span lengthens. KEME itself doubles as an attack tool: resynthesizing LongMemEval trajectories around fixed answers with semantically similar distractors dropped NaiveRAG from fifty to forty percent accuracy at top-ten retrieval and from forty to twenty at top-five, and EverMemOS from one hundred to ninety, by pushing supporting evidence roughly ten percentage points deeper in normalized embedding-similarity rank without lengthening trajectories; the failure case analysis shows retrieval dominated by vague but topically adjacent memories like mid-tier elite band phrasing while the exact status transition sat unused in the store.

Skeptical assessment. This is a technical report from a vendor ecosystem evaluating largely third-party memory layers, so some design choices favor the native integration scenario, and the synthesized data inherits whatever biases GPT-5.1 and GPT-5.2 brought to persona generation despite the quality pipeline; the authors flag noise and coarse user modeling themselves in the limitations section. Token costs reported are sobering, with top systems spending thousands of tokens per trajectory on memory construction, which no phone battery will tolerate. What transfers immediately: preserve fine-grained originals over aggressive summarization, instrument your temporal ordering handling, add abstention calibration before preference inference, and stop treating captions as sufficient visual memory. Bottom line: MobileMem sets a realistic bar for personal-agent memory and shows the current field clears it only partially even in the cloud-grade configurations tested. Run your own memory stack against it before shipping anything claiming to learn from a year of use.
